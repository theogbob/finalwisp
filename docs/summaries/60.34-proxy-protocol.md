# 60.34 PROXY protocol v1/v2: as built (60.20 W2)

Research and pre-spec: 60.28 "PROXY protocol" (a research branch (not published): prototype, both design reviews). Decisions:
Q5 a separate `--proxy-protocol-from` (required for tcp), Q6 a fixed 4-6 s header timeout, `--proxy-protocol tcp|unix`.
It uses the Handoff kind byte kept by C7 (60.31). Code: `server/src/proxyproto.rs` (the pure parser), `worker/proxy.rs`
(take, the pending map, pending_add / pending_event / pending_drop / pending_sweep / pending_close),
`worker/conn.rs` (accept_on: L_PROXY, the source check, charge() extracted from accept, route -> take),
`worker/mod.rs` (Config::proxy_*, Worker::pending, dispatch, the run() wake rule, shutdown_step), `worker/connect.rs`
(inbox_ready -> take), `worker/sweep.rs`, `net.rs` (L_PROXY), `cli.rs`, `main.rs` (Config, capability note, warning),
`metrics.rs` (pp_* counters, last). Operations: 40.01 "Reverse proxy" (PROXY part) and "Logging"; flags: 40.03 "PROXY
protocol"; compat: `tests/compat/proxyproto.py` (wispsuite step `proxyproto`, port B+96); fuzz: `proxy-parse`.

## Decisions as built
1. `--proxy-protocol tcp|unix[,..]` (repeatable; its own --config list group: a command-line value replaces the file's,
   review) and `--proxy-protocol-from CIDRS` (its own list group). Startup errors (exit 2, cli::check on the final
   command line): `tcp` without `--proxy-protocol-from`, `--proxy-protocol-from` without `tcp`, `unix` without
   --listen-unix. A warning when the list holds 0.0.0.0/0 or ::/0. Capability line: `, proxy protocol: tcp (from N
   ranges), unix`.
2. Strict per listener (spec: the receiver must not guess): every connection on it must start with a header. TCP: the
   peer must be in --proxy-protocol-from, checked right after the --max-conns reservation (RST, reservation released,
   pp_refused); accept4 then always reads the sockaddr on that listener. Unix: always allowed (the file mode).
3. Load counted once, at accept, on the final owner (route; a --balance or unix hand-over happens before the header).
   `take` (route and inbox_ready) puts an L_PROXY connection in `Worker::pending` (HashMap by fd, outside the slab: no
   Client slot, no buffer; empty and unallocated when off), registered EPOLLIN|EPOLLRDHUP|EPOLLET as
   tok(K_LISTEN, PENDING0 + fd) with PENDING0 = 2 (K_LISTEN 0 = TCP, 1 = unix); pending_add peeks at once (the header
   usually came with the handshake). It does not touch load.
4. pending_event: recv(MSG_PEEK) into a 4096-byte stack buffer = proxyproto::MAX_HEADER (the largest header: 16 + the
   v2 length field; nginx's limit); Partial waits (a new segment is a new edge; Partial with RDHUP/HUP/ERR is dropped:
   the rest cannot come); Bad = RST (pp_bad); Done = recv(len) consumes exactly the header (a short read = RST), so a
   TLS ClientHello or the HTTP request stays queued; the source replaces the peer (none = the real peer: LOCAL, UNSPEC,
   UNKNOWN, AF_UNIX, and an unspecified or 100::/64 source, which can never become the unix sentinel); `charge` (the
   60.22 direct-peer charge, now one helper for accept and here) after the header; then EPOLL_CTL_DEL and adopt (its ADD
   reports the queued bytes: no lost edge). pp_ok, and pp_local (a part of pp_ok, counted after the charge: review).
5. One release helper, `pending_drop` (out of the map, close, RST unless EOF, `unload(None)`: load and the
   reservation; no key exists yet). Its callers: the epoll ADD failing (that path releases directly), EOF / error,
   Bad, a short consume, the per-IP refusal after the header (refuse_ip_conns), the timeout and STOP_CLOSE. After adopt
   the 60.22 exits release load, reservation and key.
6. Timeout via the idle sweep: PROXY_SWEEPS = 3 sweeps of 2 s = 4-6 s (up to ~8 s once after an idle gap, as HS_SWEEPS;
   compat measured 6.5 s); pp_timeout. run() also wakes for sweeps while `pending` is not empty.
7. Shutdown: STOP_CLOSE closes every pending connection (pending_close); STOP_DRAIN leaves them to their timeout.
8. Trust order: PROXY decides who the peer is, then the 60.22 rules run on that peer: a source not in --trusted-proxy is
   charged after the header and its X-Forwarded-For is ignored; a source in it (a CDN edge behind the NLB) is not
   charged, its X-Forwarded-For is walked at the upgrade (compat: `ip=9.9.9.9 via=10.1.1.1`). The invariant "charge
   skips trusted peers" (the upgrade.rs debug_assert at the key overwrite, 60.31) holds for header sources too;
   mutation (charge trusted peers): two worker tests fail. Unix + PROXY: a header source is an untrusted client; LOCAL
   keeps the trusted unix sentinel (its X-Forwarded-For is read: compat `ip=5.5.5.5 via=unix`).
9. --log-conns: `ev=conn_refused` for a refused source (`why=protocol_error`, the peer), a bad header
   (`protocol_error`), the timeout (`hs_timeout`), the per-IP refusal after the header (`limit`, ip = the header's
   client, not the balancer: review). A connection closed before any byte (a TCP health check) gives no line.
10. Parser (proxyproto.rs, ~110 lines + tests): v2 signature / version 2 / command 0-1 / families 0x11, 0x21, 0x31,
    0x00; UDP families and short address blocks Bad; TLVs skipped (no CRC32C); a length over the cap is Bad as soon as
    the 16-byte prefix is in. v1: CRLF within 107 bytes, no bare CR or LF anywhere before it (the fuzz target found an
    `UNKNOWN` line with a bare LF accepted on the whole input but Bad on a prefix: fixed, in the regress corpus),
    `TCP4`/`TCP6` with strict addresses (the family must match) and ports (no leading zero), `UNKNOWN`. A prefix that
    cannot become a header (`GET /`, a ClientHello) is Bad at once. Mapped IPv4 is canonical.
11. At memory level 2-3 (accept paused) a header that completes is still adopted (60.28: bounded by --max-conns and the
    6 s). Not changed.

  `tls_drive`, `read_target`, `write_target`, `flush_pending`, `flush_bucket`, `stage_upload`, `pend_account`,
  `after_write`, `push_continue`, `close_target`, `proxy_io`, `stream_token`, `log_close`, `line_head`, plus `adopt`,
  `unload`, `try_connect`, `start_connect`, `new_target`, `resolve`, `won`, `ws_fail`, `proxy_fail`, `proxy_connect`.
- New: `listen_event`, `pending_event`, `pending_drop`, `pending_sweep`, `pending_close`, `take`, `charge`,
  `proxyproto::usable`, `u32::from_ascii_bytes_radix_impl`, the `HashMap<RawFd, Pending>` monomorphs.
- Logic, cold: `accept_on` (734 -> 608 lines: the source check is added, the per-IP charge moves out to `charge`);
  `log_refused` (same length: the listener-kind label is now a 3-entry table, `L_PROXY`); `main`, `cli::parse_args`,
  `Stats::help`/`named` (5 counters appended), the `Opts`/`Config` drop glue (`proxy_from` box).
- Logic, `Worker::run` (11852 -> 11821 lines). With registers masked and nops dropped, about 550 of 11.6k lines differ;
  most of that is block reordering and a register swap (`self` moved from %rbp to %r13). The real changes: the
  K_LISTEN arm calls `listen_event` (out of line), the sweep wake test adds `|| !pending.is_empty()`, and the inlined
  `inbox_ready` calls `take` where it called `adopt`. `listen_event`, `pending_sweep`, `pending_close` and
  `pending_drop` are `#[inline(never)]` (cold): inlined, the match and the sweep moved more of run. run is per-event,
  not per-byte; an OFF A/B of run's loop is the lead's call (60.20 rule).
