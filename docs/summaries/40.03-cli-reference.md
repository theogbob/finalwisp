Drift check for a new build: the block above must equal `finalwisp --help 2>&1` byte for byte (copy the lines
between the fences and compare them with the output, e.g. with `diff`). If it differs, update this doc.

Rules: options are read left to right and the last one wins (`--port 7000 --port 7001` = 7001; a switch such as
`--no-splice` cannot be undone later in the line). A bare number is the port (PORT). `--mem-budget`, `--download-rate`, `--upload-rate-per-stream`, `--upload-rate` and `--upload-rate-per-ip` take K, M or G
(powers of 1024); every other number is a plain integer (`--notsent-lowat 131072`, not `128K`). Unknown arguments exit 2. Rule from 60.16: a flag is in `--help` and in this doc, or it does not exist.

## Client IP and per-IP limits (60.20 C2 / C3b; off by default; as built: 60.22)
| flag | default | values | effect |
|---|---|---|---|
| --trusted-proxy CIDRS | none | `IP` or `IP/len`, list | peers whose client-IP header is believed (only these; from any other peer the header is ignored). A warning if it holds 0.0.0.0/0 or ::/0 |
| --real-ip-header NAME | x-forwarded-for | header name | the one header read from a trusted peer (case-insensitive). `x-forwarded-for`: a list, walked right to left skipping trusted hops; any other name (`x-real-ip`, `cf-connecting-ip`): one value. No fallback to a second header; RFC 7239 `Forwarded` not supported |
| --max-conns-per-ip N | 0 (off) | u32 | at most N connections per client key (IPv4 address, IPv6 /64) across all threads. Direct peers over it: RST at accept (before TLS); behind a trusted proxy: 429 after the HTTP request. metric refuse_ip_conns |
| --stream-rate-per-ip R[/B] | off | R 1..1000000 per second, burst B (default 2R) | a token bucket per client key: one token per CONNECT (also UDP) and per wsproxy upgrade; empty: CLOSE 0x49 (wsproxy: 429). metric refuse_ip_rate |
The key table holds at most 65,536 keys (64 shards x 1024); when a shard is full a new key is not limited (fail open,
metric ip_untracked; --max-conns stays the backstop). Metrics also: realip_bad, realip_missing, ip_keys_max.

## Bandwidth caps (60.30 C10a; off by default; research 60.26)
| flag | default | values | effect |
|---|---|---|---|
| --download-rate RATE | 0 (off) | bytes/s: 0, or 16K..4095M | the most the server sends on one client connection per second (all its streams together, Wisp and wsproxy). Kernel TCP pacing (SO_MAX_PACING_RATE) set once on each listener and inherited by every accepted socket; no per-byte work. Also turns splice off and lowers the client lowat to max(16 KiB, RATE/8) (never above --notsent-lowat; `--notsent-lowat 0` stays the kernel default) |
| --upload-rate-per-stream RATE | 0 (off) | bytes/s: 0, or 16K..4095M | the most the server sends to one TCP target per second (each stream on its own, not shared). Set on the target socket when it connects, with TCP_NOTSENT_LOWAT max(16 KiB, RATE/8); a socket that refuses either option fails its stream with CLOSE 0x03 (metric pace_fail) |
RATE uses the --mem-budget grammar: plain bytes or K/M/G = KiB/MiB/GiB per second. In Mbit/s (x 8.39): 128K = 1.05,
1M = 8.39, 10M = 83.9, 100M = 839, 1G = 8590. The capability line shows both forms (`pacing: download/conn 1048576 B/s
= 8.4 Mbit/s (splice off)`).
What the cap is: an upper bound on TCP payload bytes per second on that socket (Wisp/WebSocket/TLS framing counts,
TCP/IP headers do not), with bursts: the first 10 segments of each connection are unpaced. Measured 0.96-1.02 of the
cap at 10 and 100 Mbit/s, 0.92-1.05 at 1 Mbit/s (60.26). Not a byte quota; nothing is refused. Limits (40.01
"Bandwidth caps"): UDP upload is not capped; there is no per-IP total; a download cap also slows the same connection's
upload. Startup refuses to run if the kernel does not pass the listener's cap to accepted sockets (self-check).

## Upload caps (60.25 C10b; off by default)
| flag | default | values | effect |
|---|---|---|---|
| --upload-rate R[/B] | off | bytes/s with K/M/G: R 8K..1T; burst B >= 16K and >= R/10, default max(R, 16K) | the most finalwisp reads from one client connection per second (all its streams together: TCP, UDP and wsproxy, with WebSocket and Wisp framing; not the TLS handshake). Over it the client is not read (metric upl_pauses) and TCP flow control holds the sender; nothing is dropped or refused. Startup line `upload cap: R B/s burst B per connection` |
| --upload-rate-per-ip R[/B] | off | as --upload-rate | the same, shared by all connections of one client key (C3b keys: IPv4 /32, IPv6 /64; behind a reverse proxy only with --trusted-proxy, else every client is the proxy). Waiting connections of a key are served in order (no starvation; metric upl_ip_waits). A key the table cannot track (full shard) is not limited per IP (fail open, 60.18 #17); --upload-rate still applies. Startup line `per-ip: ... upload R B/s burst B` |
Unlike --upload-rate-per-stream (kernel pacing of what finalwisp sends to a target), these limit what finalwisp reads
from the client, so they also cover UDP streams and wsproxy. All streams of a limited connection wait together (one TCP
connection). Precision on loopback (compat uplimit): 0.98-1.0 of the cap after the burst. Operations: 40.01 "Upload
caps"; design and measurements: 60.25.

## Unix socket listener (60.31 C7; off by default; research 60.28)
| flag | default | values | effect |
|---|---|---|---|
| --listen-unix PATH | off | a path of 1-107 bytes | a second listener on a unix stream socket, besides the TCP one (both serve; there is no flag to turn TCP off). For a reverse proxy on the same host. Always plain ws:// (no TLS on it, even with --tls-cert: TLS ends at the proxy). The file is created with --unix-mode; `PATH.lock` (0600) is created beside it and flocked for the life of the process, so a second finalwisp on the same path refuses to start. An existing socket nobody listens on is replaced; a live one, or anything that is not a socket, is refused (exit 1). The file is removed at a clean shutdown; the .lock file stays. Its clients are trusted like a --trusted-proxy: their --real-ip-header is read (no header = the client is `unix`, not limited per IP); --max-conns counts them. Logged as `ip=unix` (with a header: `ip=<client> via=unix`). Metric accepted_unix |
| --unix-mode OCTAL | 660 | 0..777, octal digits only | the socket file's permissions (who may connect = who may write it). Needs --listen-unix (alone: exit 2). Group access: put the socket in a directory of the proxy's group (setgid dir, or systemd `RuntimeDirectory=` + `Group=`; 40.01) |
Not on unix clients (no TCP there): --download-rate (a warning at startup), dead-peer detection, the stall shed at memory
level 2+, TCP_NODELAY / --notsent-lowat, kTLS. With --listen-unix a TCP peer whose address is exactly `100::` (the unix
clients' internal address; RFC 6666 discard-only) is reset at accept when the peer address is read (C2/C3b flags or
--log-conns; metric refuse_sentinel).

## PROXY protocol (60.34; off by default; research 60.28)
| flag | default | values | effect |
|---|---|---|---|
| --proxy-protocol tcp\|unix | off | `tcp`, `unix`, a comma list; repeatable (a command-line list replaces the --config one) | every connection on that listener must start with a PROXY protocol v1 or v2 header (HAProxy spec; AWS NLB, HAProxy `send-proxy[-v2]`, nginx `proxy_protocol on`, Envoy). No auto-detection: a connection without one is reset. `unix` needs --listen-unix. The header's source address is the client from then on (per-IP limits, --log-conns; a source in --trusted-proxy may still name the client in X-Forwarded-For). LOCAL (health checks), UNSPEC, UNKNOWN and AF_UNIX headers keep the real peer. A header must be complete within 4-6 s (up to ~8 s after an idle period) and at most 4096 bytes; TLVs are skipped |
| --proxy-protocol-from CIDRS | none | `IP` or `IP/len`, list; required with `tcp` | the TCP peers that may send the header (the load balancers); any other peer is reset at accept (metric pp_refused). A warning if it holds 0.0.0.0/0 or ::/0 (right only when the network lets nothing but the load balancer reach the port, e.g. an NLB with client-IP preservation behind a security group). Separate from --trusted-proxy: who may send the L4 header and who may send X-Forwarded-For are different questions. Unix peers always may (the socket file's mode is the guard) |
Errors at startup (exit 2): `--proxy-protocol tcp` without `--proxy-protocol-from`, `--proxy-protocol-from` without `tcp`,
`unix` without --listen-unix. The capability line shows `proxy protocol: tcp (from N ranges), unix`. Metrics: pp_ok,
pp_local (a part of pp_ok), pp_bad, pp_timeout, pp_refused; a per-IP refusal after the header counts in refuse_ip_conns.

## Destination policy (60.20 C1; off by default except the address classes; design 60.02 C1, as built 60.21)
Refusals are CLOSE 0x48 (wsproxy: HTTP 403 before the 101 for a request rule). Lists are comma-separated; a repeated flag
appends; a list given on the command line replaces that list from --config (each list alone). Request rules run on the
CONNECT before the stream cap, memory admission and DNS (a refused name is never looked up or cached); address rules
run on every resolved address (only allowed addresses are connected to: no rebinding window).
| flag | default | values | effect |
|---|---|---|---|
| --allow-host NAMES | none | host names | only these names and the names below them (`example.com` matches `a.example.com`, not `notexample.com`); any other name is refused. ASCII as sent (IDN as punycode `xn--`), case and one trailing dot ignored; no regex, no wildcards. IP literals skip host rules |
| --block-host NAMES | none | host names | refuse these names and every name below them; wins over --allow-host. Cannot see CNAMEs: hard blocks belong in --block-dest |
| --allow-ports LIST | none | `[tcp:\|udp:]N[-M]` | only these ports for that protocol (an allow list for TCP leaves UDP open unless it has one too) |
| --block-ports LIST | none | `[tcp:\|udp:]N[-M]` | refuse these ports; wins over --allow-ports |
| --block-smtp | off | | = `--block-ports tcp:25,tcp:465,tcp:587`. Without it (and no port rule covering them) startup prints a one-line hint |
| --no-direct-ip | off | | refuse a CONNECT to an IP literal, incl. the inet_aton forms (`127.1`, `2130706433`, `0x7f000001`, `0177.0.0.1`: a numeric last label) |
| --no-ipv6-targets | off | | drop IPv6 target addresses (an IPv4-mapped one counts as IPv4), refuse IPv6 literals, and send no AAAA query (getaddrinfo AF_INET; --dns-own asks A only) |
| --allow-dest CIDRS | none | `IP` or `IP/len` | an explicit exception: these addresses pass every class (loopback, private, own, embedded); not --block-dest, not --no-ipv6-targets |
| --block-dest CIDRS | none | `IP` or `IP/len` | refuse these addresses; checked first. A public IP that is not on an interface (cloud 1:1 NAT, EC2 elastic IP) needs this |
| --allow-self | off | | let clients reach the server's own interface addresses (startup snapshot; loopback ones stay under --allow-loopback). Default blocked: WISP-over-WISP recursion and services a cloud firewall protects from outside |
| --allow-embedded-v4 | off | | let clients reach IPv6 forms that carry IPv4 (`::/96`, 6to4 `2002::/16`, Teredo `2001::/32`, local-use NAT64 `64:ff9b:1::/48`); then ::/96 and 6to4 are judged by their IPv4, Teredo and local-use NAT64 stay private. `::ffff:0:0/96` and the NAT64 well-known `64:ff9b::/96` are always judged by their IPv4 (DNS64 on IPv6-only boxes; decision 60.18 #15) |

## Upstream proxy (60.32 C6; off by default; research 60.27)
Every TCP stream goes out through one SOCKS5 or HTTP CONNECT proxy. Without the flag nothing changes (direct egress).
| flag | default | values | effect |
|---|---|---|---|
| --upstream URL | none | `socks5://`, `socks5h://` or `http://`, then `[USER[:PASS]@]HOST[:PORT]` | the proxy for every TCP stream. Ports default to 1080 (socks5) and 80 (http). USER and PASS are percent-decoded (1-255 bytes each; RFC 1929 SOCKS auth or HTTP Basic). HOST is a name, IPv4, or `[IPv6]` (an IPv6 address without brackets is refused). A name is resolved at startup (no address = startup error) and again every 30 s on the `upstream-dns` thread (a failed refresh keeps the last list). A secret flag (C8): a `--config` file that holds it should be mode 0600, and the URL's userinfo is shown as `***@` in every line |
| --upstream-trust-dns | off | switch | required with `socks5h://`, refused otherwise: the proxy resolves the names (ATYP 3, sent as an absolute `name.`) |
Refused at startup with a clear message (exit 2): `https://` (TLS to the proxy is not supported; use `http://` or
`socks5://`), any other scheme, a path, query or fragment, port 0, bad `%`-escapes, `socks5h://` without
`--upstream-trust-dns`.
With an upstream: UDP streams get CLOSE 0x48 and the UDP extension is not advertised; no TFO to the proxy; no early DNS
answers (--dns-own waits for the final answer). DNS, the destination policy (60.21) and the address rules run locally as
without a proxy, before the proxy is contacted, and only IP literals go to the proxy (`socks5://`, `http://`). With
`socks5h://` + `--upstream-trust-dns` names go to the proxy unchecked by the address rules: the request rules (host,
port) still apply, and inet_aton forms (`127.1`) and loopback names (`localhost`, `*.localhost`, `localhost6`,
`ip6-localhost`, ...) are refused without --allow-loopback.
CLOSE reasons: SOCKS REP 02 / HTTP 403 = 0x48; REP 03, 04 = 0x42; REP 05 = 0x44; REP 06 / HTTP 504 = 0x43; the proxy
unreachable = the connect errno's code (refused 0x44); auth failure, a broken reply, other codes = 0x03. A refusal about
the target (REP 03-06, HTTP 500/502/503/504) tries the next target address over a new proxy connection, at most 4
addresses, all within one --connect-timeout. Metrics: upstream_ok, upstream_fail (40.01).

## Opt-in (off by default)
| flag | what it does | when |
|---|---|---|
| --balance | new connections go to the least loaded thread instead of the kernel's SO_REUSEPORT choice | a few busy long-lived connections on a big box: churn/rr +4..11 % on 36-72 thread boxes. Costs on connection churn: connchurn rps -0.6..-7.5 % in 7 of 8 cells (one +1.1 %; one handoff per accepted connection), echo 100x10 up to -2.6 %. Stays opt-in (60.15 T21) |
| --tcpmem-adapt | 20.31 B3: near the host's TCP memory pressure (net.ipv4.tcp_mem) this server's REMOTE sockets take the level-1 caps and credit; a loopback peer or a peer on our own local address is never capped by it (a peer on another of the box's addresses counts as remote, 20.31) | a small VPS whose tcp_mem collapses under many fast streams (the only sysctl-free remedy). Needs credit v2, the memory budget, cgroup v2 socket accounting, SO_BUF_LOCK (5.15+) and the host network namespace; the capability line says why it is off otherwise. Kept opt-in (60.18 #2) |
| --max-conns N | 60.20 C3a: at most N client connections in the process (one exact reservation across the threads, taken before a --balance hand-over). Over it a new connection is reset (RST) right after accept, before any TLS or HTTP work; metrics refuse_conns, conns_reserved / conns_max | a hard cap per process (fd budget, a fair share on a shared box). It is a policy limit: the memory budget (levels) stays the safety net and still pauses accepting under memory pressure (then connections wait in the backlog instead) |
| --max-streams-per-conn N | 60.20 C3a: a CONNECT when that connection already has N streams (resolving, connecting or open; TCP and UDP) gets CLOSE 0x49, the connection stays; a stream that ends frees its slot. Metrics refuse_limit (apart from the memory refusals refuse_admit / refuse_streams). wsproxy connections have one stream and are not counted | one client cannot open thousands of streams (a port scan or a stream flood inside one WebSocket); 64-256 is generous for browsers |

## Advanced / diagnostic (leave at the default unless a problem points here)
| flag | default | what it turns off or changes | evidence for the default |
|---|---|---|---|
| --graceful-close | RST close | FIN instead of RST when a client closes a finished stream | RST: churn 18k -> 119k streams/s, p99 39 -> 2.3 ms, TIME_WAIT 25k -> ~60 (20.06 T6) |

## Config file: --config FILE (60.20 C8)
- The file holds the same flags as the command line, one per line: `flag value` or a bare `flag`, with the long option
  names **without** the leading dashes. Blank lines and lines starting with `#` are skipped. The value is the rest of
  the line with the outer whitespace trimmed: no quoting, and a `#` after a value is part of it (`motd hi # x` sets
  the MOTD to `hi # x`). A repeated key appends (list flags: `tls-cert`/`tls-key`, `dns-server`, `cert-auth-key`).
- The file's flags take the place of `--config FILE` on the command line, so one parser checks everything:
  - a flag **after** `--config` overrides the file's value, a flag before it is overridden by the file (last wins);
  - a list flag given **anywhere** on the command line replaces the file's whole list (no merging; `--tls-cert` and
    `--tls-key` count as one list) (60.18 #13 a);
  - a bare flag in the file (e.g. `balance`) cannot be switched off on the command line: remove the line.
- Errors exit 2 before any socket is opened: unreadable or missing file, a directory, larger than 1 MiB, a line longer
  than 16 KiB, invalid UTF-8, a control character, an unknown or removed flag, a value on a bare flag or none on a value
  flag, a bad value, `config` inside the file (no includes), `--config` given twice. The message names `FILE:LINE` and
  the flag but never the value (the file may hold secrets); a name that does not look like a flag is not shown either.
- The capability line ends its first part with `config FILE`. A flag whose value is a secret (none yet; C6 `--upstream`
  URLs with credentials will be one) in a file readable by group/others gives a startup warning.
- `PORT` without a flag name is not accepted in the file: write `port 7000`.

Example (`/etc/finalwisp.conf`, `finalwisp --config /etc/finalwisp.conf`):
```text
# finalwisp behind nginx on the same host
host 127.0.0.1
port 6001
motd welcome
auth-file /etc/finalwisp/passwords
dns-server 10.0.0.53
dns-server 10.0.0.54
mem-budget 1G
```

## Removed in base-4 (60.18)
`--credit-v2`, `--prio`, `--no-tcpmem-adapt` (no-op aliases of the default) and `--no-dns-coalesce` (coalescing is always
on). A start command that still passes one exits 2, for example:
```text
finalwisp: --credit-v2 was removed in base-4 (60.18): upload credit v2 is the default (--no-credit-v2 turns it off); drop it
```
Migration: delete the flag from the unit file or the container command. The server then behaves as it did with the
flag (the three aliases), or keeps coalescing on (`--no-dns-coalesce`). Last-wins trap: an alias that came after its
opposite switched it back. `--tcpmem-adapt ... --no-tcpmem-adapt` ran with adaptation OFF; after deleting
`--no-tcpmem-adapt` it runs ON, so delete `--tcpmem-adapt` too. The same holds for `--no-credit-v2 ... --credit-v2` and
`--no-prio ... --prio` (60.16).
