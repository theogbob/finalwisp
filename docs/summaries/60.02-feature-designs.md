## 0. Rules shared by every feature

1. **Off = absent.** Each feature is an `Option<Box<..>>` (or an empty list) in `Arc<Config>`, decided at startup.
   Off means `None`: no allocation, no per-worker state, no struct growth.
2. **Hooks only at control points:** accept (`accept_all`/`adopt`), upgrade (`handle_http`), CONNECT (`on_connect`,
   `new_target`, `start_connect`), connect completion (`won`/`connected`), close (`close_target`, `close_client`), and
   the existing timers (`idle_sweep`, every 2 s). No hook in `read_target`, `splice_target`, `flush`, `flush_upload`,
   `write_target`, `read_udp`, `udp_send`. Exceptions: C10 (data path while on, by definition) and one `rx_bytes` add
   per client read syscall for C5 (section C5, measured).
3. **No struct growth when off.** Per-client or per-stream data a feature needs (client IP, log fields, proxy
   handshake state) lives in side vectors parallel to the `Slab` index (`Vec<T>` sized like `clients.slots` /
   `targets.slots`), allocated only when the feature is on. `Client` and `Target` stay the same size, so the idle
   KiB/connection and per-stream memory do not move when the feature is off.
4. **Cross-worker state** only where the semantics need it (C3 per-IP and total counts). It is touched at accept and
   close, never per packet. Metrics use owner-written relaxed atomics (plain `mov` on x86-64/aarch64, no locked RMW).
5. **Refusals use Wisp CLOSE reasons consistently:** policy = `0x48` (Blocked), limits/pressure = `0x49` (Throttled),
   name has no address / unreachable = `0x42`, timeout = `0x43`, refused = `0x44`, other network/proxy error = `0x03`.
   All four other servers use 0x48 for policy and 0x49 for limits (wisp-js `HostBlocked`/`ConnThrottled`, epoxy
   `ServerStreamBlockedAddress`, python 0x49, mrrowisp `closeReasonBlocked`/`closeReasonThrottled`).
6. **Gate per feature** (60.01 principle 2): OFF vs `base-1` on `regress.py --suite lo,tls,idle` (must tie every case);
   ON cost on the cases named in each test plan. Needed harness change: `regress.py --new-args "..."` (flags for the
   new build only; today `--args` goes to both builds, and `base-1` does not know the new flags).

## C1. Destination policy
Status (2026-11-01): **built** (60.20 W1 step 3); the as-built spec, the decisions that changed this design (two Q2
flags, --allow-dest lifts every class, no `@FILE`, no SIGHUP refresh of the own addresses, NAT64 pending) and the
release-note lines are in 60.21.

### What the others do
| | wisp-js | epoxy-server | python | mrrowisp | finalwisp today |
|---|---|---|---|---|---|
| host rules | regex, whitelist XOR blacklist (whitelist wins, blacklist ignored) | RegexSet allow/block, global + per TCP/UDP; allow = exception to block | none | exact-match set (FILTER-2: `sub.`, trailing dot bypass) | none |
| matched on | requested name | requested name | - | lowercased name, trailing dot stripped | - |
| port rules | list/ranges, whitelist XOR blacklist | ranges, block unless allowed | none | set/ranges, whitelist XOR blacklist | port 0 refused (0x41) |
| direct IP | `allow_direct_ip` (ipaddr.isValid) | `allow_direct_ip` (Rust parse) | always allowed | `AllowDirectIP` (net.ParseIP) | always allowed |
| IP classes checked | after one lookup, one address only | after resolve, **first address only** | after resolve, first address | first allowed address; **whitelisted names skip the check** | **every** resolved address; disallowed ones dropped |
| connect uses | a 2nd lookup (cache TTL bug: 120 compared with ms, so ~no cache: rebinding window) | the checked IP | checked IP; socks5h: raw name, no check (PY-NEW-2) | checked IP; with proxy: the raw name (CVE-CANDIDATE-5) | the checked IPs (no TOCTOU) |
| IPv6 | allowed | `resolve_ipv6` (default off) | allowed | allowed | allowed |
| refusal | 0x48 | 0x48 (no address: 0x42) | 0x42 for everything | 0x48 (DNS fail 0x42) | 0x48 (all addresses filtered), 0x42 |

### Semantics we pick
Evaluation order in `on_connect` (wsproxy: in `handle_http` before `new_target`), cheapest first, stop at the first
refusal:
1. **Stream type**: UDP with `--no-udp` (existing). Today this answers 0x41; propose 0x48 like the other four servers
   (Q7). Unknown type stays 0x41.
2. **Port rules** (TCP and UDP separately). Port 0 stays 0x41.
3. **Direct IP**: with `--no-direct-ip`, a host that is an IP literal is refused (0x48). "IP literal" = Rust `IpAddr`
   parse succeeds, **or** the last label is numeric (all digits, or `0x` + hex), the WHATWG URL rule. This catches
   inet_aton forms that `getaddrinfo` accepts and turns into addresses: `127.1`, `2130706433`, `0x7f000001`,
   `0177.0.0.1`. A DNS name cannot have an all-numeric TLD, so no real name is lost. `[::1]` (brackets) is not an IP
   for `IpAddr::parse` and fails DNS (0x42) as today.
4. **Name rules** on the requested name, **before DNS**. Normalized in a stack buffer: ASCII lowercase, one trailing
   dot removed (browsers send punycode, so no IDN work). An entry `example.com` matches `example.com` and every
   subdomain (`a.b.example.com`), never `notexample.com`. Matching walks the labels (`a.b.example.com`,
   `b.example.com`, `example.com`, `com`) against a `HashSet<Box<str>>`: O(labels), no regex. Literal IPs skip name
   rules (they get address rules in step 6).
   - **block wins:** a name on the block list is refused even if it is also allowed (this allows "allow
     `example.com`, block `admin.example.com`").
   - **allow list = default deny:** if any allow-host entry exists for the stream's protocol, a name that matches no
     allow entry is refused.
   - Refused before DNS: no lookup, no DNS-cache entry, no negative-cache entry (attacker names cannot fill the cache).
5. **DNS** (existing: IP literal, positive cache `DNS_TTL` 30 s, negative cache `DNS_NEG_TTL` 5 s, pool). Unchanged.
6. **Address rules** on **every** resolved address in `start_connect` (where `Filter::allowed` runs today). An address
   is kept only if all hold, in this order:
   - not in a `--block-dest` CIDR (explicit block always wins);
   - IPv6 allowed (`--no-ipv6-targets` drops v6 addresses; an IPv4-mapped v6 counts as IPv4);
   - in an `--allow-dest` CIDR (operator exception: overrides the built-in loopback/private classes), **or** passes
     the existing class filter (`--allow-loopback`, `--allow-private`).
   - Name allows never override the class filter. That is deliberate (mrrowisp lets a whitelisted name resolve to
     private space; that is the CVE-CANDIDATE-5 rebinding hole).
   - Disallowed addresses are dropped and the rest go to Happy Eyeballs (today's behaviour, unlike epoxy, which
     refuses when the first address is bad). Nothing left: 0x48 if the name had addresses, 0x42 if it had none.
7. **Class filter hardening** (same function, `v4_class`/`v6_class`): add as "private" the IPv6 forms that embed or
   reach IPv4 (PY-NEW-6): `::/96` IPv4-compatible (`::7f00:1`), `2002::/16` 6to4 (classify the embedded IPv4), Teredo
   `2001::/32`, local-use NAT64 `64:ff9b:1::/48` (`64:ff9b::/96` is already private), site-local `fec0::/10`,
   discard `100::/64`. This changes the default filter for odd ranges only (Q2).
8. **Self-connection** (SSRF-5: WISP-over-WISP recursion that gets a fresh per-connection budget; also reaches services
   on the host's public IP that a cloud firewall protects from outside). Proposal: at startup the main thread reads
   the interface addresses (`getifaddrs`) and treats them as loopback class (blocked unless `--allow-loopback`).
   It refreshes on SIGHUP (Arc swap). This is a default-behaviour change (Q2).

Rule syntax (one parser for CLI and TOML): list values are comma-separated; any list value `@FILE` reads one entry per
line (`#` comments). An optional `tcp:` / `udp:` prefix restricts an entry to one protocol, for example
`--allow-ports tcp:80,tcp:443,udp:53,udp:443`. Port entries: `N` or `N-M`. CIDR entries: `10.0.0.0/8`,
`2001:db8::/32`, or a bare IP (= /32 or /128).

### Flags and config keys (C8 keys in brackets)
- `--allow-host LIST` [`policy.allow_hosts`], `--block-host LIST` [`policy.block_hosts`]
- `--allow-ports LIST` [`policy.allow_ports`], `--block-ports LIST` [`policy.block_ports`]
- `--allow-dest CIDRS` [`policy.allow_dests`], `--block-dest CIDRS` [`policy.block_dests`]
- `--no-direct-ip` [`policy.direct_ip = false`], `--no-ipv6-targets` [`policy.ipv6_targets = false`]
- existing, renamed only in TOML: `--allow-loopback` [`policy.allow_loopback`], `--allow-private`
  [`policy.allow_private`], `--no-udp` [`policy.udp = false`]
- Names follow the roadmap ("block") and epoxy (`allow_*`/`block_*`), which makes epoxy configs easy to port (minus regex).

### Hooks and state
- `Config.policy: Option<Box<Policy>>`. `Policy { ports: [Bitmap65536; 2] (8 KiB each, tcp/udp; allow and block
  folded into one bit at startup), allow_hosts/block_hosts: [HashSet<Box<str>>; 2], allow_dests/block_dests:
  Vec<(u128, u8)> (v4 stored mapped), direct_ip: bool, ipv6: bool }`. Immutable, shared, no per-worker state.
- `net::Policy::check_request(stype, host, port) -> Result<(), u8>` called in `on_connect` after the existing
  validation and before `new_target`. `net::Policy::addr_ok(ip) -> bool` replaces the `filter.allowed` closure in
  `start_connect` when `Some`; when `None` the existing `Filter` runs unchanged.
- deliberate: CIDR lists are a linear scan (fine for hundreds of entries; a prefix trie only if a user loads big lists).
- `--no-ipv6-targets` also sets `ai_family = AF_INET` in `net::lookup` (one less AAAA query per name). The DNS pool is
  shared and the policy is global, so this is safe.
- **Cost when off:** one `Option` test per CONNECT. Nothing per packet. Cost when on: a bitmap lookup, 2-5 hash
  lookups and a short CIDR scan per CONNECT.

### Interactions
- Happy Eyeballs (20.14) races only kept addresses; HE memory (20.24) is keyed by IP and is unaffected.
- DNS cache (20.23): name refusals happen before the cache; the cache keeps unfiltered addresses (the policy is static,
  and filtering per CONNECT keeps one cache valid for TCP and UDP).
- TFO (20.15): checks run before the deferred connect, so the ClientHello still rides the SYN.
- splice/kTLS, two lanes: not touched. The CLOSE for a refusal goes to `obuf` through `push_wisp` as today.
- Memory budget (20.26): policy runs before admission, so a blocked CONNECT never takes budget.
- UDP: same rules, with `udp:` entries; `udp_open` uses the same filtered address list.

### Security notes and safe defaults
- Defaults unchanged: loopback and private blocked, everything public allowed. Safe-default additions proposed:
  embedded-IPv4 ranges (step 7) and self addresses (step 8), see Q2.
- Hard blocks belong in address rules: name rules cannot see CNAME chains (FILTER-2 "CNAME"); document that.
- Rebinding: closed by design (we connect to exactly the addresses we checked). Keep it that way in C6 too.
- SMTP (SSRF-4) and port scans: a documented example `--block-ports tcp:25,tcp:465,tcp:587`; default stays open
  (Q3). Scans are better handled by the C3 stream rate.
- Hostname length is already capped (`MAX_HOST` 255; FILTER-3/HIGH-4).

### Test plan
- Rust unit tests (`net.rs`): suffix matching (case, trailing dot, sibling names), numeric-TLD rule, ports bitmap
  with prefixes, CIDR v4/v6/mapped, block-wins, class filter for every new range.
- `tests/compat/policy.py BIN PORT` (new; spawns servers with flags, local TCP/UDP echo targets on 127.0.0.x, uses
  `--allow-loopback` where needed):
  - port allow/block, ranges, `tcp:`/`udp:` prefix: right stream gets 0x48, others connect;
  - `--block-host blocked.test`: `x.blocked.test`, `BLOCKED.TEST.` give 0x48 **at once** (before DNS: an unblocked
    unresolvable name would give 0x42), `notblocked.test` gives 0x42;
  - allow list: `--allow-host localhost` without `--allow-loopback` still gives 0x48 (name allows do not lift classes);
  - `--no-direct-ip`: `127.0.0.1`, `127.1`, `2130706433`, `0x7f000001`, `::ffff:127.0.0.1` give 0x48;
  - `--no-ipv6-targets`: `::1` gives 0x48; `localhost` (::1 + 127.0.0.1) connects over IPv4;
  - `--allow-dest 127.0.0.2/32` without `--allow-loopback`: 127.0.0.2 connects, 127.0.0.3 gives 0x48;
  - wsproxy path: a refused target closes the WS (same rules); UDP streams: same rules.
- Existing gates unchanged (`adversarial.py`, `v2ext.py`, `udp.py`, wisp-js).
- regress.py: OFF vs base: all cases. ON (a realistic rule set, e.g. 3 port rules + 50 host rules + 10 CIDRs, with
  `--allow-loopback`): watch `churn 10x10` and `rr 10x10` (CONNECT rate); data cases must tie.

## C2. Real client IP (X-Forwarded-For / X-Real-IP, trusted proxies only)
Status (2026-11-01): **built** with C3b (60.20 W1 step 4). Changed from this design: the flag is --trusted-proxy; a
missing header is not charged (fail open); no --conn-rate-per-ip yet. As built: 60.22.

### What the others do
| | header | trust | parsing |
|---|---|---|---|
| wisp-js | XFF, else X-Real-IP | `parse_real_ip_from` exact IP list, **default on** with `127.0.0.1` | **leftmost** XFF entry (client-controlled when the proxy appends) |
| epoxy | X-Real-IP, else XFF | `use_real_ip_headers` bool, **no trust list** | whole header value as a string; used for log ids only |
| python | X-Real-IP | only if peer is 127.0.0.1 (hardcoded) | raw value |
| mrrowisp | configurable list (`trustedHeaders`) | `trustedProxies` CIDRs | **right to left, skipping trusted entries**; first untrusted valid IP |

### Semantics we pick
- On only when `--trust-proxy` lists at least one CIDR (or with a C7 unix listener, whose peers count as trusted).
- If the TCP peer is not in a trusted CIDR, headers are ignored and the client IP is the peer (no spoofing from the
  internet).
- One header, chosen explicitly: `--real-ip-header` = `x-forwarded-for` (default) | `x-real-ip` |
  `cf-connecting-ip` | any name. No automatic fallback to a second header: the proxy may overwrite one header and pass
  the other through from the client.
- **XFF parsing (mrrowisp / nginx `real_ip_recursive` rule):** all XFF header lines are joined with `,` in order
  (RFC 9110 field-line combination). Walk entries right to left; skip entries in trusted CIDRs; the first untrusted
  entry is the client. Every entry trusted: use the leftmost. An entry may carry a port (`1.2.3.4:5678`,
  `[2001:db8::1]:443`); strip it. An unparsable entry (`unknown`, obfuscated `_hidden`) ends the walk: the client IP is
  the last trusted hop we passed (the proxy), and the counter `realip_bad` is incremented. That is fail-safe for limits
  (the proxy shares one key, it does not get a fresh one per request).
- Single-value headers (`x-real-ip`, `cf-connecting-ip`): one IP (port stripped); unparsable: the peer, `realip_bad`.
- IPv4-mapped IPv6 (`::ffff:1.2.3.4`) is normalized to IPv4 (the peer too, when the listener is dual-stack).
- The result is used for C3 per-IP limits and C4 logs. It never changes routing or policy.
- PROXY protocol v1/v2 (HAProxy, AWS NLB, L4 load balancers) is not part of C2 (Q8).

### Flags and keys
`--trust-proxy CIDRS` [`client_ip.trusted_proxies`], `--real-ip-header NAME` [`client_ip.header`].

### Hooks and state
- `accept_all`: pass a `sockaddr_storage` to `accept4` instead of null when any of C2/C3/C4 is on (the kernel copies
  28 bytes; nothing extra when off). With `--balance` the IP travels with the fd (`Inbox.fds` becomes
  `Vec<(RawFd, IpAddr)>` only in that mode, or `adopt` calls `getpeername` once when on).
- `http::parse` gets an optional header name to capture (`Request.fwd: Option<String>`); with C2 off the header
  loop is unchanged.
- `handle_http`: after parse, compute the client IP and store it in the side vector `client_ip: Vec<IpAddr>` (indexed
  like `clients.slots`, allocated only when on). For trusted-proxy peers, C3 per-IP checks run here (see C3).
- **Cost when off:** none (no sockaddr, no header capture, no side vector). When on: one header compare per header
  line at upgrade, plus 16-24 bytes per live client in the side vector.

### Interactions
TLS: no effect (the header arrives inside TLS). wsproxy: same. Memory budget: the side vector is part of the anon
usage the sampler already sees. No data-path effect.

### Security notes and safe default
Default off (unlike wisp-js, which trusts `127.0.0.1` out of the box: a local reverse proxy that does not overwrite
XFF then lets anyone pick their own IP). Leftmost-entry parsing (wisp-js) and trust-everything parsing (epoxy) are
both spoofable. Startup warning if `--trust-proxy` contains `0.0.0.0/0` or `::/0`.

### Test plan
- Unit tests (`http.rs`): right-to-left walk, all-trusted, ports, brackets, junk entries, multiple header lines,
  mapped IPv6.
- `tests/compat/realip.py` (new): server with `--trust-proxy 127.0.0.1/32 --log-conns`; client bound to 127.0.0.1
  sends XFF variants; check `ip=` in the connection log. Client bound to 127.0.0.2 (untrusted): header ignored.
  Combined with `--max-conns-per-ip 2`: two connections with XFF A, third with A refused (HTTP 429), one with B
  accepted.
- regress.py: OFF: all. ON: `idle` (KiB per connection, side vector) and `churn`; data cases must tie.

## C3. Limits (policy limits, separate from the 20.26 memory budget)
Status (2026-11-01): **C3a done** (60.20 W1: `--max-conns` as one exact process-wide reservation taken right after
accept4 and released with `Inbox.load` in Worker::unload, incl. both adopt failure exits; `--max-streams-per-conn`
before memory admission; RST at accept, refuse_conns / refuse_limit / conns_reserved). **C3b built** with C2
(--max-conns-per-ip, --stream-rate-per-ip; 60.22).

### What the others do
- wisp-js: `stream_limit_total` per connection and `stream_limit_per_host` (0x49); no per-IP limits.
- epoxy: none (only the optional bandwidth limit; see C10).
- python: "connections" per IP per **fixed window** (default 30/60 s) that actually counts streams; 0x49. Per process,
  so N processes = N x the limit (PY-NEW-5); fixed window allows 2x bursts (RESOURCE-3, HIGH-3).
- mrrowisp: `MaxConcurrentStreamsPerConnection`, `MaxConcurrentConnections` (semaphore), per-source connects/s and
  per-destination connects/s/min (fixed windows despite the name `SlidingWindow`), in-flight SYN cap; 0x49.
- Report: unbounded streams per connection (CRITICAL-1, RESOURCE-1: 44k streams/s), wsproxy bypasses limits (HIGH-7).

### Semantics we pick
| limit | key | checked in | refusal |
|---|---|---|---|
| `--max-streams-per-conn N` | connection | `on_connect` (`c.streams.len() >= N`) | CLOSE 0x49 on that stream; connection stays |
| `--max-conns N` (total) | process | `accept_all` (sum of `Inbox.load`, which exists) | close with RST (`linger_zero`), before any TLS/HTTP work |
| `--max-conns-per-ip N` | client IP key | `accept_all` (direct peer) or `handle_http` (trusted proxy, after C2) | direct: RST; proxied: `429 Too Many Requests` + close |
| `--conn-rate-per-ip R[/B]` | client IP key | same as above | same as above |
| `--stream-rate-per-ip R[/B]` | client IP key | `on_connect` | CLOSE 0x49 |

- **Rate = token bucket** (rate R per second, burst B, default B = 2R): no fixed-window double burst. State per key:
  `tokens: f32, last: u32` (coarse ms).
- **IP key:** IPv4 = the /32 address. IPv6 = the /64 prefix by default (one subscriber normally gets a /64 or more;
  per-address keys are trivially bypassed by rotating addresses). `--ipv6-prefix-len` 32..128. Mapped IPv6 = IPv4.
  No IP (unix socket without a header) = one shared key `unix`.
- `--limit-exempt CIDRS`: keys never limited (monitoring, health checks). The trusted proxy itself is **not** exempt
  automatically: with C2, limits apply to the real IP behind it.
- Stream rate exists because a port scan or SYN flood runs inside one WS connection: connection limits do not see it
  (mrrowisp's per-source connects/s counts dials for the same reason).
- wsproxy counts as one connection and one stream (closes HIGH-7).
- UDP streams count toward streams-per-conn and the stream rate.
- Order in `on_connect`: C1 policy (0x48), then the streams-per-conn check, then the stream rate, then 20.26 admission
  (0x49). A refused CONNECT never takes a token from the per-IP bucket if policy already refused it.

### Hooks and state
- `Config.limits: Option<Box<Limits>>`.
- Cross-worker table (SO_REUSEPORT hashes the 4-tuple, so one IP's connections land on every worker: per-worker
  counts would allow N x threads): `IpTable { shards: [Mutex<HashMap<IpKey, Entry>>; 64] }`, shard = hash(key) & 63.
  `Entry { conns: u32, conn_bucket, stream_bucket }`. Touched at accept, at upgrade (proxied case), at CONNECT (stream
  rate) and at `close_client` (decrement). Never per packet.
- Entries are removed when `conns == 0` and both buckets are full (sweep in `idle_sweep`, one shard per sweep per
  worker). Size cap per shard (e.g. 16k entries): when full, new keys are not tracked (fail open for rates, counted in
  `limits_untracked`); `--max-conns` stays the backstop. Fail-closed would let one attacker with many IPv6 /64s lock
  everyone out.
- Side vector `client_key: Vec<IpKey>` (shared with C2's `client_ip`) so `close_client` can decrement the right key.
- **Cost when off:** one `Option` test at accept, CONNECT and close. Nothing per packet. When on: one uncontended
  mutex per accept/close (~20-50 ns) and per CONNECT with a stream rate.

### Interactions
- Memory budget (20.26): independent. Pressure L2 pauses `accept()`; `--max-conns` refuses. Both can apply. Metrics
  label the reason (`limit` vs `pressure`) because both use 0x49.
- DNS overload (`DNS_INFLIGHT_MAX`, 0x49) stays as is.
- `--balance`: counts and checks happen in the accepting worker before the hand-off.
- TLS: direct-peer refusals happen before the handshake (no rustls work for refused clients).

### Security notes and safe defaults
All off by default (feature rule). For a public server the recommended starting point goes into the docs, not into
defaults: `--max-streams-per-conn 256 --max-conns-per-ip 32 --conn-rate-per-ip 10/30 --stream-rate-per-ip 50/200`
(Q4: should any of these become a default?). Self-recursion (SSRF-5) is covered by C1 step 8; when loopback is
allowed, nested connections come from our own address and share that key.

### Test plan
- Unit tests: IP key masking (/64, /48, mapped), token bucket refill and burst, entry eviction.
- `tests/compat/limits.py` (new): streams-per-conn: stream N+1 gets 0x49, the connection keeps working, after one
  CLOSE a new stream succeeds. `--max-conns 3`: the 4th TCP connection is reset before 101. Per-IP: sources 127.0.0.1
  vs 127.0.0.2 (bind). Rates: burst B accepted, then 0x49/RST, refill after 1/R s. wsproxy counted. With `--threads 4`:
  the per-IP limit holds across workers (open 2N connections from one IP, expect exactly N accepted).
- regress.py: OFF: all. ON (limits high enough not to trigger): `churn 10x10`, `rr 10x10`, `idle`.

## C4. Log levels and structured connection log

### What the others do
- wisp-js: `logging.info` per connection (IP, origin), per-stream warnings on errors; debug for DNS.
- epoxy: `log_level` (default info); stream open/close at debug with `[client id] [stream uuid]`.
- python: `--log-level`; info per connection, warn per failed stream.
- mrrowisp: `logLevel`, structured key/value (`Logger.Warn("egress block", "ip", ...)`), a warn line per blocked dial.
- finalwisp today: startup lines only; workers never log.

### Semantics we pick
- `--log-level error|warn|info|debug` (default `info`). Info = startup/capability lines, warnings, the periodic
  metrics line (C5). No per-connection lines unless asked (roadmap).
- `--log-conns`: one line at connection close (and one at open in debug). `--log-streams`: one line per stream close
  (including refusals with the rule that refused). Both off by default.
- Format: logfmt, one line per event, stable keys (`--log-format json` later if wanted, Q5). Examples:
  ```
  ts=2026-10-24T12:00:00.123Z lvl=info ev=conn_close w=3 cid=3:1842 ip=203.0.113.9 via=10.0.0.2 tls=1 proto=v2 auth=password dur_ms=93812 streams=41 rx=18234 tx=91823412 why=client_close
  ts=... lvl=info ev=stream_close cid=3:1842 sid=7 t=tcp host=example.com port=443 dst=93.184.215.14 conn_ms=23 up=1832 down=873421 reason=0x02
  ts=... lvl=info ev=refused cid=3:1842 sid=9 t=tcp host=10.0.0.1 port=22 reason=0x48 rule=private
  ```
  `ip` = C2 client IP (peer if C2 off), `via` = trusted proxy peer if any. `why` (connection) is one of client_close,
  ws_error, protocol_error, hs_timeout, auth_failed, tls_error, pressure_shed, limit, server_close.
- Byte counts without data-path work:
  - stream `up`/`down`: `TCP_INFO` on the target socket at close (`tcpi_bytes_acked` = bytes the target acked,
    `tcpi_bytes_received` = bytes from the target; Linux 4.1+; the raw-buffer approach of `net::delivery_rate`).
    UDP streams: datagram and byte counters kept in the existing per-datagram loops of `udp_send`/`read_udp`, only
    when `--log-streams` is on.
  - connection `rx`/`tx`: `TCP_INFO` on the client socket at close (wire bytes, TLS records included).
- **Writer:** workers never call `write(2)` on stderr (a slow journald or a full pipe would stall the event loop).
  Each worker appends lines to a local `Vec<u8>`. At the end of a loop turn that logged something, it moves them to
  its `Mutex<Vec<u8>>` outbox (one lock per turn). A `log` thread swaps the outboxes every 100 ms and writes them to
  stderr (blocking is fine there). Outbox cap 1 MiB per worker: beyond it lines are dropped and counted, and the log
  thread prints `ev=log_dropped n=...`.
- **Flood control:** refusal lines (C1/C3) are limited per worker to 20/s; beyond that one line per second with
  `ev=refused_suppressed n=...`. A port scan cannot turn into a disk-filling log.
- Timestamps: `CLOCK_REALTIME_COARSE` (vDSO), formatted in the worker only when a line is written.

### Flags and keys
`--log-level` [`log.level`], `--log-conns` [`log.connections`], `--log-streams` [`log.streams`],
`--log-format` [`log.format`, later].

### Hooks and state
- `Config.log: LogCfg` (level, two bools; all false/info by default).
- Call sites: `close_client` (connection line), `close_target` (stream line; refusals when `t.state` never reached
  Open), `handle_http` (open line, debug), `accept_all` (refused by C3).
- Per client (side vector, only with `--log-conns`): `cid: u64`, `start_ms: u32`, `streams: u32`, `why: u8`, `proto:
  u8`, `auth: u8`. The `why` value is set at the existing `begin_close`/`ws_fail`/`wisp_reject`/`close_client` call
  sites.
- Per stream (side vector, only with `--log-streams`): `host: Box<str>` (today the host string is moved into the DNS
  request and dropped), `start_ms: u32`, UDP counters.
- **Cost when off:** one predictable branch at connection close and stream close. No struct growth (side vectors), no
  thread (the log thread starts only if any line can be produced above startup). When on: one `getsockopt` per stream
  close and per connection close, line formatting, one mutex per loop turn that logged.

### Interactions
splice/kTLS/two lanes: untouched (bytes come from the kernel at close). TFO: a stream whose ClientHello rode the SYN
is counted by the target's `bytes_acked` like any other. Memory budget: the outbox cap bounds log memory (1 MiB x
threads); pressure-shed streams log `reason=0x49 rule=pressure`. HE: `dst` is the winning address (`net::peer_ip` is
already called in `won` for multi-attempt races; single attempts know it).

### Security notes
Destination hostnames are browsing data: per-stream logs are off by default and the docs say so. Never log passwords,
key material, the auth file path contents, or upstream proxy credentials (C6 redacts the URL userinfo). Log lines are
built from validated values only (hostnames are UTF-8 checked; escape `"`, `\`, control bytes in logfmt values, so a
crafted hostname cannot forge log lines).

### Test plan
- `tests/compat/logs.py` (new): default run: no per-connection lines. `--log-conns --log-streams`: parse logfmt,
  check keys, `up`/`down` against a known transfer (within framing), refusal lines with `rule=`. Refusal flood of 1000
  blocked CONNECTs: at most ~20 lines + a suppressed line. Stalled stderr (pipe the server's stderr into a reader
  that stops reading): `echo.py` still completes and `log_dropped` appears once the reader resumes.
- regress.py: OFF: all. ON (`--log-conns --log-streams`, stderr to a file): `churn 10x10`, `rr 10x10`, `idle`; data
  cases must tie.

## C5. Metrics

### What the others do
- epoxy: optional `stats_endpoint` (same server path or a separate listener): JSON with every client, every stream
  (requested and resolved target), jemalloc stats **and the serialized config, including
  `password_extension_users`** (a secret leak if the endpoint is reachable).
- wisp-js, python: none. mrrowisp: log lines and reputation counters, no endpoint.

### Semantics we pick
- Counters per worker in `Arc<WorkerStats>` (one cache-line-aligned struct per worker, `AtomicU64` fields). Only the
  owning worker writes, with `store(load() + n, Relaxed)` (compiles to plain load/add/store; no `lock` prefix, no
  cache-line sharing between workers). Readers sum all workers on demand.
- Event counters, incremented where the event already happens (not per packet): connections accepted / refused (by
  reason), streams opened (tcp/udp), CLOSE reasons sent (array indexed by reason code), connect errors (refused,
  timeout, unreachable), DNS cache hit/miss/negative hit, DNS overload (0x49), Happy Eyeballs: races with more than
  one attempt, wins by the second family; TFO SYNs with data; kTLS handshakes / KeyUpdates; splice pipe creations and
  "pipe refused" fallbacks (30.09); pressure sheds (20.26); C2 `realip_bad`; C3 `limits_untracked`; C4 `log_dropped`.
- Gauges: open connections (sum of `Inbox.load`, exists), open streams (per-worker `targets` slab count, published in
  `idle_sweep`), kTLS clients, clients with a splice pipe, memory level / budget / usage (from `mem::LEVEL` and the
  20.26 sampler), DNS cache entries, HE memory entries, process RSS (`/proc/self/statm`, read by the reader).
- **Bytes:** download = `Client::tx_bytes` (20.21, already counted for every send and splice). Upload = a new
  `Client::rx_bytes += n` per client read syscall (up to 256 KiB each, so ~1 add per 64-256 KiB; the same class of
  cost as `tx_bytes`). `idle_sweep` already walks every client every 2 s; it publishes the worker totals (closed
  clients' bytes + live clients' bytes). Bytes metrics therefore have 2 s resolution and no extra per-packet work
  beyond the one add. If the OFF A/B shows that add, it goes behind `if cfg.metrics` (decided by measurement).
- Output 1: `--metrics-interval SECS` (default 0 = off): one `ev=metrics` logfmt line per interval, written by the
  log thread (C4), with deltas per second.
- Output 2: `--metrics-listen ADDR:PORT` (default off; plain HTTP, `GET /metrics`, Prometheus text format 0.0.4). A
  dedicated `metrics` thread with a blocking listener: no worker involvement, no epoll registration. Only a separate
  listener (no path on the public Wisp port), so it cannot be exposed by accident; a warning at startup if the
  address is not loopback/private.
- Names (all prefixed `finalwisp_`): `connections_total`, `connections_open`, `connections_refused_total{reason}`,
  `streams_total{type}`, `streams_open`, `stream_close_total{reason="0x02"..}`, `connect_errors_total{kind}`,
  `bytes_total{dir="up|down"}`, `dns_cache_total{result}`, `dns_overload_total`, `happy_eyeballs_total{result}`,
  `tfo_syn_data_total`, `ktls_clients`, `splice_pipes`, `memory_level`, `memory_budget_bytes`,
  `memory_usage_bytes`, `process_resident_bytes`, `worker_connections{worker}` (for `--balance` decisions).
  No per-client or per-destination labels (cardinality and privacy).

### Flags and keys
`--metrics-listen ADDR:PORT` [`metrics.listen`], `--metrics-interval SECS` [`metrics.interval`].

### Hooks and state
`Worker.stats: Arc<WorkerStats>` (~1 KiB per worker); `Client::rx_bytes: u64` (fills existing padding or +8 bytes;
check with `size_of::<Client>()`, Q6). Increments at: `accept_all`, `on_connect`, `new_target` (DNS cache result),
`won` (HE), `try_connect` (TFO), `close_target` (reason array), `tls_finish`, `key_update`, `idle_sweep`
(publication), 20.26 shed/admission sites.

**Cost when off:** the event adds are always compiled in (they run at accept/CONNECT/close, never per packet), so
"off" means no thread and no listener. The one per-read `rx_bytes` add is the only data-path change; it must tie in
the OFF A/B (download/upload/echo 1x1 and 10x10), otherwise it is gated.

### Interactions
splice/kTLS: `tx_bytes` already includes splice and kTLS sends (`tx_count` in `flush`/`send_bulk`). Two lanes: both
lanes go through `tx_count`. Memory budget: reads the existing atomics. UDP: `udp_send`/`read_udp` add datagram
counters per batch (recvmmsg returns up to 8; one add per batch).

### Security notes
No secrets or config in the output (contrast: epoxy stats). Loopback by default when only a port is given. No auth on
the endpoint: bind it to loopback or a private interface, or put it behind the reverse proxy.

### Test plan
- `tests/compat/metrics.py` (new): run N connections x M streams with known bytes; scrape; check counters
  (connections, streams, close reasons, bytes within framing overhead), monotonic between scrapes, gauges back to 0
  after close; text format parses; no `password`/`auth` strings in the output. `--metrics-interval 1`: lines appear.
- regress.py: OFF: all (the `rx_bytes` add is in every build). ON (`--metrics-listen` + a scraper at 1/s):
  `download 10x10`, `churn 10x10`.

## C6. Upstream proxy (SOCKS5 and HTTP CONNECT)

### What the others do
- python: `--proxy socks5h|socks5|socks4a|socks4|http://...` via python-socks. With remote DNS it skips **all** IP
  checks and sends the raw name (PY-NEW-2, CHAIN 2: `metadata.google.internal` reaches 169.254.169.254). UDP with a
  proxy: refused (exception, so CLOSE 0x42).
- mrrowisp: `proxy` URL; always SOCKS5 (socks5h and socks5 both rewritten to `socks5://`), checks the locally resolved
  address, then dials the **name** through the proxy (TOCTOU, CVE-CANDIDATE-5). No proxy auth support. UDP with a
  proxy: CLOSE 0x48.
- wisp-js, epoxy: no upstream proxy.

### Semantics we pick
- `--upstream URL` with schemes `socks5://`, `socks5h://`, `http://`. Userinfo (`user:pass@`) allowed, but the
  recommended form is `--upstream-auth-file FILE` (one line `user:pass`, mode warning like `--auth-file`), because
  argv is world-readable in `/proc/*/cmdline`.
- **DNS mode:**
  - `socks5://` and `http://` (local DNS, default): we resolve, apply every C1 rule to every address, then hand the
    proxy an **IP literal** (SOCKS ATYP 1/4, `CONNECT [v6]:port`). The proxy connects to exactly what we checked:
    no rebinding, no TOCTOU.
  - `socks5h://` (or `--upstream-dns remote`): we send the **name** (ATYP 3 / `CONNECT name:port`) and do not resolve
    locally. Needed for Tor (`.onion`) and split-horizon setups. C1 name and port rules still apply; address rules and
    the loopback/private classes apply only to IP literals, because we never see the resolved address. Startup
    warning: `upstream socks5h: loopback/private checks are delegated to the proxy`. Q1: allow this silently, require
    an explicit acknowledgement flag, or refuse unless the proxy is known to filter?
- **The proxy address itself is exempt from the destination policy** (it is often on loopback or a private network).
  It is resolved once at startup; its addresses are tried in order.
- **SOCKS5 (RFC 1928/1929):** greeting `05 01 00` (no credentials) or `05 01 02` (credentials: offer only user/pass, so
  a misconfigured proxy cannot silently fall back to no auth). Method reply `FF` or auth status != 0: fail. Then
  `05 01 00 ATYP ADDR PORT`; reply `05 REP 00 ATYP BND.ADDR BND.PORT`, read to its exact length (it depends on ATYP).
  One step at a time (no pipelining; the proxy is normally near, and strict servers reject pipelined requests).
  BIND and GSSAPI: not supported.
- **HTTP CONNECT (RFC 9110 9.3.6):** `CONNECT host:port HTTP/1.1\r\nHost: host:port\r\n[Proxy-Authorization: Basic
  b64(user:pass)\r\n]\r\n`. The response is parsed with `httparse::Response` (already a dependency), header cap 8 KiB.
  2xx = open.
- **Bytes after the reply** (a server-first target such as an SMTP banner can arrive in the same read as the SOCKS
  reply or the `200`): kept and delivered to the client as the first DATA (copy path once), then normal operation.
- **Client DATA during the handshake** stays in `Target::pend` (as during a normal connect) and is flushed by
  `connected()` after the proxy says yes: order is preserved, nothing is written to the proxy before that.
- **Failure mapping to Wisp CLOSE:**
  | event | CLOSE |
  |---|---|
  | cannot reach the proxy, proxy closes, malformed reply, method/auth rejected, HTTP 407 | 0x03 (+ rate-limited warn log: an operator problem, not the target's) |
  | SOCKS REP 0x02 (ruleset) / HTTP 403 | 0x48 |
  | SOCKS REP 0x03, 0x04 / HTTP 502 | 0x42 |
  | SOCKS REP 0x05 | 0x44 |
  | SOCKS REP 0x06 / HTTP 504 / our `--connect-timeout` (covers proxy connect + handshake + target connect) | 0x43 |
  | SOCKS REP 0x01, 0x07, 0x08, other HTTP status | 0x03 |
  In local-DNS mode a target-side failure (REP 0x03/0x04/0x05) tries the next resolved address with a new proxy
  connection, within the same deadline (sequential; see HE below).
- **UDP:** HTTP CONNECT cannot carry UDP. SOCKS5 UDP ASSOCIATE needs a control connection plus a per-datagram header
  (10-22 bytes, wrap/unwrap = a copy per datagram) and many proxies (Tor) do not support it. First version: with an
  upstream, UDP streams are refused with CLOSE 0x48, and the v2 INFO does not advertise extension 0x01 (clients do not
  try). `--upstream-udp direct` lets UDP bypass the proxy (it exposes the server's own egress IP; Q1b). UDP ASSOCIATE
  is a later option if a user needs it.

### Flags and keys
`--upstream URL` [`upstream.url`], `--upstream-auth-file FILE` [`upstream.auth_file`],
`--upstream-dns local|remote` [`upstream.dns`; `socks5h://` implies remote], `--upstream-udp refuse|direct`
[`upstream.udp`].

### Hooks and state
- `Config.upstream: Option<Box<Upstream>>` (`kind`, proxy `Vec<SocketAddr>`, credentials, dns mode, udp mode).
- New `TState::Proxy` between `Connecting` and `Open`.
- `try_connect`: when `Some`, connect to the proxy address instead of `SocketAddr::new(ip, port)` (TFO off: the SYN
  cannot carry a ClientHello for the proxy). In remote-DNS mode `new_target` skips DNS and goes straight to the
  deferred connect with the name kept in the side vector.
- `won` -> instead of `connected()`: enter `TState::Proxy`, write the greeting, keep the target on the `connecting`
  list (the existing deadline scan in `run_timers` times it out).
- `target_event` `TState::Proxy` arm -> `proxy_step(ti)`: non-blocking read/write of the handshake. Done: `connected()`
  (unchanged); leftover bytes go to the client as DATA.
- Handshake state in a side vector `proxy_hs: Vec<Option<Box<ProxyHs>>>` (`ProxyHs { step, buf: [u8; 512], len,
  addr_idx }`), freed when Open. Allocated only with `--upstream`.
- **Cost when off:** one `Option` test in `try_connect` and `won`; the extra `TState` arm is never taken. Nothing per
  packet. When on: one proxy TCP connect + 1-3 round trips per stream (to the proxy), ~0.5 KiB during the handshake.

### Interactions
- Happy Eyeballs: no race through the proxy (the proxy does the real connect; parallel attempts would double the load
  on it). Addresses are tried in our interleaved order, sequentially. HE memory is neither read nor written for
  proxied streams.
- DNS cache: local mode uses it as today; remote mode never touches the DNS pool (`DNS_INFLIGHT_MAX` irrelevant).
- TFO: off for proxied streams (documented). Data queued during the handshake still goes out right after it.
- splice/kTLS/two lanes: after the handshake the target fd is an ordinary TCP socket, so the splice download path and
  the upload writev batching work unchanged. TCP urgent data (20.25) depends on the proxy forwarding it (usually not).
- Memory budget: the proxy socket is a target socket (20.26 `cap_bufs` applies). `--abort-close` RST closes the proxy
  connection; the proxy then closes upstream.
- C1/C3 run before any proxy work; a blocked CONNECT never reaches the proxy.

### Security notes
- The SSRF guard stays in finalwisp in local-DNS mode (contrast PY-NEW-2 / CHAIN 2). Remote mode is an explicit
  choice with a startup warning (Q1).
- Credentials: never logged; the startup line prints the URL with userinfo redacted.
- Plain HTTP CONNECT sends Basic credentials in clear text: warn at startup if the proxy address is not loopback or
  private. HTTPS proxies (TLS to the proxy) are out of scope.

### Test plan
- `tests/compat/upstream.py` (new, stdlib): a small SOCKS5 server (no auth / user-pass) and an HTTP CONNECT proxy
  (Basic auth) in the test process, recording what they receive. Cases: socks5 gets an IP literal, socks5h gets the
  name; wrong password gives 0x03; REP 0x02/0x04/0x05 map to 0x48/0x42/0x44; HTTP 407 -> 0x03, 403 -> 0x48; a stalled
  proxy -> 0x43 at the deadline; a target that writes a banner immediately: the banner arrives (leftover path); DATA
  sent before the reply arrives in order; UDP CONNECT -> 0x48 and the v2 INFO lacks extension 0x01; policy: socks5 to
  `10.0.0.1` -> 0x48 and the proxy saw nothing; a bulk download through the proxy uses the splice path (check with
  C5 `splice_pipes` > 0).
- regress.py: OFF: all. ON: not comparable on throughput (the proxy dominates); measure handshake latency with
  `bench/connect_latency.py` against a local SOCKS5 server, and check that `download 10x10` through the proxy keeps
  the zero-copy path (CPU per byte close to direct).

## C7. Unix socket listener
`--listen-unix PATH` [`listen.unix`] with `--unix-mode 0660` [`listen.unix_mode`]. Linux has no SO_REUSEPORT for
AF_UNIX stream sockets, so one listening fd is shared: every worker adds it to its epoll with `EPOLLEXCLUSIVE` (no
thundering herd) and calls `accept4` (EAGAIN is normal). TCP-only socket options (`TCP_NODELAY`,
`TCP_NOTSENT_LOWAT`, TFO, `TCP_INFO`) are skipped for unix clients; the splice download path works (splice into an
AF_UNIX socket is supported); kTLS needs TCP, so `--tls-cert` with only a unix listener is refused at startup (TLS
terminates in nginx/Caddy in this setup). A unix peer has no IP: with C2 configured its header is trusted (the peer is
local by construction), otherwise the client key is `unix`. A stale socket file is removed at startup only if it is a
socket and `connect()` to it fails. The TCP listener stays available (both may run). Cost when off: none (no fd, no
epoll entry). C4 connection lines with no TCP_INFO report `rx`/`tx` from the C5 counters instead.

## C8. Config file (TOML)
`--config FILE`. Keys mirror the flags: section = feature (`[listen]`, `[tls]`, `[policy]`, `[client_ip]`,
`[limits]`, `[log]`, `[metrics]`, `[upstream]`, `[dns]`, `[memory]`), key = flag name without `--` and the section
prefix, `-` -> `_`, plural for repeatable flags (`--block-host` -> `policy.block_hosts = [...]`). The section/key
names in this document are the contract. CLI overrides file: a scalar flag replaces the file value; a list flag
replaces the whole file list (no merging: merging hides rules). Unknown keys are an error (typo safety), and so are
type mismatches. Secrets stay in referenced files (`auth_file`, `upstream.auth_file`), never inline. Startup only;
SIGHUP reload of `[policy]` lists (Arc swap of `Policy`) is a later step. Dependency choice (Q9): `toml` + `serde`
(compile time and binary size, startup only) or a small hand parser for the subset we use (strings, ints, bools,
string arrays, sections).

## C9. Custom DNS servers / result order
`getaddrinfo` cannot take a server list. Options: (a) document a local caching resolver (unbound,
systemd-resolved) and keep the system path; (b) a minimal UDP/TCP DNS client in the DNS pool threads (A + AAAA, TC
fallback to TCP, random IDs and source ports, retries; ~300-400 lines and security-sensitive: spoofing). Recommend
(a) now, plus the cheap part: `--dns-order system|ipv4|ipv6` [`dns.order`] (a stable partition before
`net::interleave`, 20.14). No hot-path cost either way (DNS pool + cache already off the event loop). Keep
`--dns-threads`/`--no-dns-coalesce` as `dns.threads`/`dns.coalesce`.

## C10. Bandwidth limit (opt-in)
Per connection: download via `SO_MAX_PACING_RATE` on the client socket (kernel TCP pacing, works with splice and
kTLS, zero user-space cost; enforced in the kernel's own pacing since Linux 4.13, no fq qdisc required). Upload: the
Wisp credit is the lever: a limited connection stops reading the client (like 20.26 `mpaused`) when its byte bucket is
empty and resumes from the 100 ms timer tick. Per IP: one shared bucket per C3 key (cross-worker, atomic token
counters touched per read only while the limit is on), or per-connection rate = IP rate / connections of that key
(cheaper, approximate). Splice: limit the `splice` length to the available tokens (up to 256 KiB per call keeps the
granularity fine). Flags: `--bw-per-conn RATE` [`limits.bw_per_conn`], `--bw-per-ip RATE` [`limits.bw_per_ip`],
RATE like `10M` (bytes/s). Cost when off: none for the pacing part; the upload/IP part adds a branch per client read,
which must tie in the OFF A/B. Python's spin-wait limiter (PY-NEW-4) is the anti-pattern: no polling loops.

## Open questions for the maintainer
- Q1. Upstream `socks5h` (remote DNS) cannot apply loopback/private checks. Allow with a warning, require an explicit
  acknowledgement flag, or refuse? Q1b: `--upstream-udp direct` at all (leaks the server's own egress IP)?
- Q2. Default filter hardening: block embedded-IPv4 IPv6 forms (`::/96`, 6to4, Teredo, `64:ff9b:1::/48`) and the
  server's own interface addresses (WISP-over-WISP recursion, cloud-firewall bypass). Both change today's defaults.
- Q3. Port 25/465/587: keep open by default (the others do) or block by default as a safe default like loopback?
- Q4. Should any C3 limit be on by default (e.g. 256 streams per connection), or all off per the feature rule?
- Q5. Log format: logfmt only, or JSON as well from the start?
- Q6. C5 `rx_bytes` add per read: accept as always-on if the OFF A/B ties (my pick), or gate it behind `--metrics`?
- Q7. `--no-udp` refusal code 0x41 -> 0x48 (what the other four servers send)?
- Q8. PROXY protocol v1/v2 (HAProxy, AWS NLB) as part of C2, or later?
- Q9. C8: `toml`+`serde` dependency or a small hand parser?
- Q10. Regex host rules for config compatibility with wisp-js/epoxy, or suffix match only (my pick: no regex, no
  ReDoS, O(labels))?
- Q11. Per-IP tables full (IPv6 /64 rotation from a /48): fail open for new keys (my pick, `--max-conns` is the
  backstop) or fail closed?
- Q12. Add `regress.py --new-args` (needed to measure every ON cost against base-1)?

## Decisions (user, 2026-10-24)
- Q1: `socks5h` allowed only with an explicit acknowledgement flag (e.g. `--upstream-trust-dns`); without it, refuse to start.
- Q1b: no `--upstream-udp direct`. With an upstream proxy set, UDP streams get CLOSE 0x48 and the UDP extension is not advertised.
- Q2: yes. Block by default: IPv4-embedding IPv6 forms (`::/96`, 6to4 `2002::/16`, Teredo `2001::/32`, `64:ff9b::/96`,
  `64:ff9b:1::/48`; IPv4-mapped `::ffff:0:0/96` judged by its IPv4 address) and the server's own interface addresses.
  This changes today's defaults: note it in the release notes; `--allow-private` does not lift it, a separate flag does.
- Q3: mail ports 25/465/587 stay open by default; one flag blocks them (e.g. `--block-smtp`); a one-line startup hint.
- Q4: no limit on by default (feature rule); the memory budget is the safety net.
- Q5: logfmt only for now; JSON later if asked.
- Q6: `rx_bytes` always on if the OFF A/B ties against base-1; else behind `--metrics`.
- Q7: `--no-udp` refusal becomes 0x48 (changes a default reason code; release note).
- Q8: PROXY protocol later, after C1-C6.
- Q9 (user: fewer libraries, as little room for bugs as possible; revisit once the base is stable): **no TOML, no serde.**
  C8 becomes a flat config file that is the CLI flags in a file: one `flag value` (or bare `flag`) per line, the same
  names as the long options without the leading dashes, `#` comments, blank lines ignored, a repeated key appends (lists).
