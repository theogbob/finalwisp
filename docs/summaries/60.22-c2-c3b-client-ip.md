# 60.22 C2 real client IP + C3b per-IP limits: as-built spec and decisions (60.20 W1 step 4)

Design: 60.02 C2 / C3 (C3b part). Decisions: 60.02 Q4, Q11; lead OK 2026-11-01. Code: `server/src/clientip.rs`
(header walk, keys, table), `net.rs` (`Handoff`, `sockaddr_ip`), `worker/conn.rs` (`accept_all`, `unload`, `adopt`,
`close_client`), `worker/upgrade.rs` (`client_ip`, `stream_token`, wsproxy), `worker/wisp.rs` (`on_connect`),
`worker/sweep.rs` (table sweep), `http.rs` (`parse_capture`). Flags: 40.03 "Client IP and per-IP limits"; operations:
40.01 "Reverse proxy".

## Decisions
1. Flags: --trusted-proxy CIDRS (its own --config list group), --real-ip-header NAME (default x-forwarded-for),
   --max-conns-per-ip N, --stream-rate-per-ip R[/B] (token bucket, B default 2R). Not built: --conn-rate-per-ip (the
   bucket code can serve it later), --limit-exempt, --ipv6-prefix-len (IPv6 key fixed at /64).
2. C2: headers only from a peer in --trusted-proxy (captured from no other peer, c2-nits); exactly one header, the configured one, matched ASCII
   case-insensitively; no fallback. XFF: lines joined in order, right to left, trusted entries skipped, the first other
   entry is the client; all trusted: the leftmost; ports and brackets stripped; mapped IPv6 = IPv4. An unparsable entry
   ends the walk at the last trusted hop (realip_bad; charged to that hop's key: fail safe). A single-value header on
   several lines = bad (not first-wins). No header: the peer, not charged (realip_missing; fail open, like C7 unix peers
   later). RFC 7239 Forwarded: not supported. The client IP never changes routing or policy.
3. Keys: IPv4 /32 (mapped form), IPv6 /64. Table: 64 shards x Mutex<HashMap> with std RandomState (SipHash, per-process
   random key: keys are attacker-chosen), shard from that hash; 1024 keys per shard (65,536 in all). A full shard
   charges no new key (Q11 fail open, ip_untracked); --max-conns stays the backstop.
4. Bucket time: u32 ms since start (wraps at ~49.7 days): refill uses wrapping_sub and is clamped to the burst. The
   clock is read before the shard lock, so a `now` up to 60 s older than the entry's time is a reordering between
   threads: no refill, the time never moves back (reviewer B review: it read as a 49-day gap, a full burst). The idle sweep
   (4 consecutive shards per sweep, every 2 s, on every awake worker: all 64 in 32 s; a stride by the thread count left
   a sleeping worker's shards unswept, reviewer B review) refills every live entry, so no entry's time ages near a wrap;
   charge refills too. Entries go at release when nothing is left (no connection, full bucket), else at a sweep (a reconnect cannot reset a
   drained bucket). Test `bucket_refill_burst_and_wrap` crosses the wrap.
5. Where counting happens: a direct peer (not trusted) in accept_all right after the C3a reservation, before
   set_nodelay and the --balance hand-over (over the limit: RST, and the C3a reservation is released at that spot); a
   trusted peer's client in handle_http right after the parse, before the Wisp / wsproxy branch (over: 429). Until its
   HTTP request a trusted peer is bounded by --max-conns and the handshake timeouts only.
6. One release helper: `unload(key)` (Inbox.load, the C3a reservation, the per-IP key) at the three exits: adopt's two
   failure exits (the hand-over's charged key) and close_client (the key taken out of `Worker::peers_of`). A key is
   released only if it was charged. Mutation check: passing None at any of the three sites fails a test.
7. push_fd payload: `Handoff { fd, peer, key }` (also for C7's listener kind later); the accepting worker's charge
   travels with the fd and the adopting worker releases it.
8. Client state: a side vector `Worker::peers_of: Vec<Option<Peer { ip, key }>>` by slab slot (empty when C2/C3b are
   off), filled when adopt succeeds, taken by close_client. Not a Client field: measured, `Option<Box<Peer>>` made the
   release slab slot `(u32, Option<Client>)` 520 bytes instead of 512 (every `Slab::at` gained a `lea`, slots no longer
   cache-line aligned); with the side vector no Client offset moves (disassembly: 60.22 below). C4 (wave 2) needs the
   peer whenever its connection log is on: the accept4 sockaddr and `peers_of` are then filled too (note at both places).
9. Stream rate: in on_connect after memory admission (no token while policy, the cap or memory refuse); 0x49,
   refuse_ip_rate. wsproxy takes one token before the 101 (429). Untracked / uncharged clients: no rate. The rate
   lives only in IpTable (has_rate; c2-nits: a second copy in ClientIp could diverge and refuse every CONNECT).
10. Metrics (appended last): refuse_ip_conns, refuse_ip_rate, realip_bad, realip_missing, ip_untracked, ip_keys_max.

## Disassembly (OFF, vs the C1 build fb5ec679)
Normalized classes (bench/tools/disasm_norm.py; `OFFSET+SYM` = only displacements and data-symbol names differ): 211
OFFSET+SYM, 12 OFFSET-ONLY, 16 LOGIC. The LOGIC ones are the changed code only: accept_all, adopt, close_client,
on_message (on_connect inlined: the stream_token test), process_input / run (inlining of the header capture), cli
parse_args, main, Opts / Config drop glue, Stats::named, the Cidr list iterator. `Slab<Client>::at` and every per-byte
function: OFFSET+SYM (Worker grew by its two new fields; Client unchanged).

## Tests
Unit: clientip.rs (keys, untrusted peer, XFF walk incl. junk / ports / brackets / lines, single-value headers, table
charge / release / shard cap fail-open, bucket refill / burst / wrap / sweep), http.rs (capture). Worker tests: charged
at accept and released at every exit (close, abort, shutdown, both adopt failures with a charged key), the --balance
hand-over carries the key, a trusted proxy's client charged at upgrade (429, missing header, spoofed header from an
untrusted peer ignored). Fuzz: http-parse walks the captured XFF against a slow reference. Compat `realip.py` (step
realip, base+8, +9).
