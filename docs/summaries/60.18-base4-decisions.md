13. (2026-11-01) 60.20 questions: (a) a list flag on the CLI REPLACES the config file's list; (b) C3b per-IP limits ship
    with C2; (c) own interface addresses: startup snapshot; (d) metrics endpoint 127.0.0.1, no auth; (e) open (user asks
    why not both download and upload caps; see lead answer); (f) open (asked what it affects); (g) C6 upstream

14. (2026-11-01) (e) early BOTH caps in Wave 2 (C10a): download per client via SO_MAX_PACING_RATE on the client socket
    and upload per stream via SO_MAX_PACING_RATE on target sockets, both set once (no per-read cost); the true per-client
    upload total (read-path token bucket) stays C10b in Wave 3. (f) unix-socket stall rule: document it (40.01), no counter.
    (g) the Go server whose upstream-proxy support a prod site relies on is wispurr: C6 is tested for parity with
    wispurr's upstream-proxy behaviour (flags, schemes, DNS handling, error codes) so sites can switch.
15. (2026-11-01) NAT64: option A. 64:ff9b::/96 (and ::ffff:0:0/96) are judged by the embedded IPv4 (net.rs
    NAT64_WKP_BY_V4 = true); ::/96, 6to4, Teredo and 64:ff9b:1::/48 stay blocked unless --allow-embedded-v4.
16. (2026-11-01) Absolute DNS names: client host names are always resolved as absolute names (trailing dot), so the
    resolv.conf search list and ndots never apply (closes the --block-host bypass via search domains; fewer queries
    under ndots:5). Both resolvers (getaddrinfo and --dns-own). Default change for base-5; verify Docker's embedded
    DNS still answers single-label container names.
17. (2026-11-02) Pre-spec questions (60.25-60.28):
    - C6 proxy facts: unknown to the maintainer ("probably not socks5h"). So: socks5:// and http:// in v1; https:// refused at
      startup with a clear error (added later if a site needs it); socks5h:// keeps the Q1 rule (needs
      --upstream-trust-dns; the error says socks5:// gives wispurr's local-DNS behaviour). Every unsupported form fails
      loudly at startup, never silently.
    - C10b per-IP table full: fail open (as Q11); the per-connection cap and --max-conns still apply.
    - Rate units: bytes/s with K/M/G (binary, the --mem-budget grammar); docs show the Mbit/s equivalent.
    - splice off when a download cap is set: yes.
    - Unix socket: mode 660, no --unix-group (user deferred to the pick; group via a setgid directory or systemd
      RuntimeDirectory= + Group=).
    - rx_bytes (C5): always on (Q6 tie after the layout control, 60.25).
