# 30.15 Cycle test: leak or retention? (30.14 watch 1; 2026-10-30)

Pointers: 30.14 (watch 1: non-pool heap minima +140-220 KiB/h in 12 h), harness bench/soak/cycle.py (branch `cycle`),
raw data (not published) (cycles.jsonl, cycles.md, samples.csv). Binary: master aa0134c + soak2 merge
(235d0c2), release md5 4161b6d2; wbench md5 3cdbfbab; VPS3, 12:34-14:34 EDT.

## Design
Fresh A (ws) + B (wss, kTLS), MemoryMax=1G scopes. 20 identical cycles: a fixed 300 s mix (download / upload / upmux 1 KiB
x 8 and 4 KiB x 6 / browse with 8 MiB bulk / 2 SIGKILLed clients; rr / churn via DNS / connchurn / udp-rr; 400 + 150
idle connections; one partial-frame burst; one probe per server), then 60 s without clients. Floor = median of the last
30 s of each idle phase. Host TCP kept low: peak 47,752 pages (tcp_mem[1] 117,275), TcpExt pressures 0, gate never hit.

## Result
- Clean: 320 wbench runs 0 bad, 40 probes 0 failed, 11,000 idle connections 0 failures, both servers exit 0. At every
  floor: 0 connections, fds 17, pool dirty 0, pool chunks 4, socket memory 0.
- cgroup anon (= the RSS rise): A 1,420 (cycle 1) -> 1,592 (2) -> 2,236 KiB (20); B 1,748 -> 1,852 -> 2,388 KiB.
  Theil-Sen over cycles 2-20: A +28 [+22, +38], B +29 [+24, +35] KiB/cycle; but it slows down: first half +50 / +41,
  second half +17 / +18, last 6 cycles +22 (A) / +6 (B) KiB/cycle; B flat at 2,376 for cycles 17-19. A log curve fits far
  better than a line (residual SS A 3.5k vs 60k, B 9.9k vs 28k).
- memory.current +95-100 KiB/cycle, linear: that is page cache of the server's own stderr log (cgroup file +64 KiB per
  cycle exactly = 72 metrics lines; harness artifact, also in 30.14's memory.current) plus anon. Kernel memory flat.

## Reading
Decelerating, retention-shaped (glibc keeps freed heap; no pool, socket, fd or connection is left behind). Not a clean
plateau yet: A still grows ~+20 KiB/cycle at the end, so a small per-cycle leak (< ~20 KiB per 5-min mix, i.e. per
~12k connections / ~1 M streams) is not excluded by 20 cycles. Next if needed: 60+ cycles (~6 h) or a heap profile
(malloc_info at each floor) to see which arena/size class grows.
