# 60.21 C1 destination policy: as-built spec and decisions (60.20 W1 step 3)

Design: 60.02 C1. Decisions: 60.02 Q2, Q3, Q7, Q10 and 60.18 #13 (a, c). Code: `server/src/policy.rs` (request
rules, entry parsers), `net.rs` `Filter` (address rules, classes, `own_addrs`), `worker/wisp.rs` `on_connect`,
`worker/upgrade.rs` (wsproxy), `worker/connect.rs` (`start_connect`, `dns_late`), `dns.rs` (`ipv4_only`). Flags: 40.03
"Destination policy"; operations: 40.01.

## Decisions (lead OK, 2026-11-01)
1. Flags: --allow-host / --block-host, --allow-ports / --block-ports (`[tcp:|udp:]N[-M]`), --allow-dest / --block-dest
   (CIDR, bare IP = /32 or /128), --block-smtp, --no-direct-ip, --no-ipv6-targets, and for Q2 two lifts:
   --allow-self (own interface addresses) and --allow-embedded-v4 (IPv6 forms carrying IPv4). Two flags: serving an app
   on the box's own public IP must not reopen 6to4 / Teredo. Each list is its own --config list group (a CLI list
   replaces that list only). No `@FILE` (long lists go into --config). Host rules have no tcp:/udp: prefix.
2. Request stage (`Policy::allows`), in `on_connect` after validation and BEFORE the C3a stream cap and memory
   admission: a refused CONNECT takes no slot, no budget, no DNS lookup, no cache entry. Order: UDP with --no-udp (Q7:
   0x48, was 0x41), ports bitmap [tcp, udp] (allow+block folded at startup, block wins, a non-empty allow list = default
   deny), direct IP (IpAddr parse, a numeric last label: inet_aton forms, or any colon: scoped `ADDR%scope` literals that
   getaddrinfo resolves numerically, review), IPv6 literal with --no-ipv6-targets, host
   rules (Q10: suffix match over a HashSet, O(labels), no regex; ASCII lowercase + one trailing dot removed in a stack
   buffer; block wins; allow list = default deny; IP literals skip host rules). `Config.policy` is None when no request
   rule is set.
3. Validation before any rule (0x41): host empty, over 255 bytes, or holding NUL / control / space / DEL; non-ASCII
   passes to DNS (IDN: names are matched as sent, punycode). Host rules do not see CNAMEs (documented in 40.01: hard
   blocks belong in --block-dest). The resolver's search list no longer applies: client names are resolved as absolute
   names since branch dns-abs (60.18 #16; this known limit is fixed).
4. Address stage (`Filter::allowed`, both filter sites, so UDP too: `udp_open` uses the filtered list). Order:
   --block-dest, --no-ipv6-targets (mapped v4 counts as v4), --allow-dest (an explicit CIDR beats every class), the
   classes (loopback: --allow-loopback; private: --allow-private; embedded: --allow-embedded-v4), then the own
   addresses (--allow-self). A name allow never lifts a class (rebinding).
5. Classes: 0.0.0.0/8 and `::` stay loopback-like (connect reaches the local host on Linux). Embedded = `::/96`, 6to4,
   Teredo `2001::/32`, the rest of `64:ff9b::/32` (incl. local-use `64:ff9b:1::/48`); with --allow-embedded-v4 the
   70.04 rule applies (::/96 and 6to4 by their v4; Teredo and local-use NAT64 private). New private: site-local
   `fec0::/10`, discard `100::/64`.
6. **NAT64 well-known prefix `64:ff9b::/96` (decided: user, 60.18 #15 option A = as built).** On an IPv6-only box with DNS64 every IPv4 target arrives in
   this form, so a hard block breaks such deployments. Lead's proposal (implemented as the default): `64:ff9b::/96`
   and `::ffff:0:0/96` are judged by the embedded IPv4. One line decides: `net.rs` `NAT64_WKP_BY_V4` (test
   `nat64_wkp_both_ways` covers both values).
7. Own addresses (Q2, decision c): `getifaddrs` once at startup, all families, minus loopback-class ones (those stay
   under --allow-loopback, so `--allow-loopback` test setups keep working). Not refreshed (no SIGHUP): an address
   change needs a restart. A public IP that is not on an interface (cloud 1:1 NAT, EC2 elastic IP) is not in the set:
   --block-dest it. The check also looks through the checkable embedded forms (mapped, ::/96, 6to4, NAT64 WKP), and so
   does an IPv4 --block-dest (review: `64:ff9b::8.8.4.4` is blocked by `--block-dest 8.8.4.4`; --allow-dest matches
   the address as resolved only). getifaddrs failing stops startup unless --allow-self (fail closed, review).
8. --no-ipv6-targets: getaddrinfo with AF_INET, and the own resolver asks A only (`Resolver::ipv4_only`: no AAAA query,
   no RESOLUTION_DELAY wait).
9. wsproxy: the request rules run before `http::switching`: 403. Address refusals come after DNS, so after the 101: a
   WebSocket close, as before.
10. Q3: a startup hint unless --block-smtp or a port rule covers 25/465/587: `finalwisp: hint: mail ports 25/465/587
    are open to clients; --block-smtp closes them`. Capability line: `, policy: ...` (rule counts, `no smtp`, `no direct
    IP`, `no IPv6 targets`, and always `own addresses blocked (N)` / `own addresses allowed`).
11. Metric `refuse_policy` (request rules, --no-udp, wsproxy 403, every address refused), appended last in `stats!`.
    Disasm vs base (3ba606b): no Stats offset moved in any hot function (repr(C) not needed). Config grew (Filter holds
    the lists), so cfg field displacements moved in accept_all, adopt, read_target, close_target, ... (all disp32 before
    and after: same instructions, same sizes). `run`: register allocation only (same calls and atomics, 2905 vs 2903
    instructions). Logic changes: on_message (on_connect inlined), process_input (handle_http / wsproxy inlined),
    start_connect, Filter::allowed, new_target (DNS cache key hash type only), dns Q::* (Ctx layout), start_dns_pool,
    main, cli::parse_args, metrics::line, Stats::named. List: raw data (not published).

## Release-note lines (base-5)
- Default change: the server's own interface addresses and IPv6 forms that embed IPv4 (`::/96`, 6to4, Teredo,
  local-use NAT64) are now blocked as targets, also with --allow-private; --allow-self / --allow-embedded-v4 restore
  base-4 behaviour. `0.0.0.0/8` and `::` stay loopback (unchanged).
- Default change: --no-udp now refuses UDP streams with 0x48 (blocked) instead of 0x41 (invalid).
- Default change: a CONNECT whose host is over 255 bytes or holds a space, NUL or control character gets 0x41 (before:
  0x42 after a failed lookup); wsproxy answers such a target with 400.
- New: destination policy flags (40.03), metric refuse_policy, the SMTP hint.
