## Harness changes for the RC soak (done, branch rcprep)
- Server logs go through a pipe to a reader thread of the harness (common.spawn_logged; soak.py A/B/F, cycle.py): the
  log's page cache is charged to the harness, not the server's scope (30.15: +64 KiB/cycle in memory.current).
  The analyzer also reports cgroup anon+kernel+sock (`*_cg_aks_kib`; never page cache) next to memory.current.
- Heap breakdown at each floor without a server change (common.smaps_breakdown: /proc/PID/smaps_rollup Rss/Anonymous
  + /proc/PID/smaps: resident anon of [heap] = glibc main arena, of the other anonymous maps = thread arenas, pool
  chunks, stacks, and their count). cycle.py: per cycle (sm_* keys in cycles.jsonl). soak.py: at the end of each quiet
  window (floors.jsonl) + analyzer section. With the pool gauges (dirty, chunks) this tells which part grows.
- soak.py `--gap-scale F` (all workload gaps x F) for the light lane.

## Pass criteria (RC fails on any)
- Every lane: 0 crashes / restarts / OOM kills / memory.max events; servers exit 0 on SIGTERM with ev=metrics_final;
  every analyzer expectation PASS (probes 0 FAIL, every wbench workload 0 bad/timeout, reaps in band, 0 false resets
  of live peers, dead-target echo OK, abuse OK, bench windows complete); pool_fallback / pool_capped /
  pool_madvise_fail / pool_munmap_fail / accept_err_* = 0 (except where the box's map_count budget is the test: then
  pool_capped > 0 is allowed, pool_fallback must still never fail a stream).
- fds, threads, pipes: flat (fds - ESTAB residual |slope| < 1 fd/h); after the clients leave: fds 17 + held half-open.
- LIGHT 1 cycle criterion (the 30.14 watch 1 verdict): cycles 1-10 = warm-up. On cycles 31-60, per server, the
  Theil-Sen slope of the cgroup anon floor has a 95 % bootstrap upper bound < 5 KiB/cycle (< 1.5 MiB/day at one
  cycle per 5 min), AND median(cycles 46-60) - median(cycles 31-45) < 128 KiB. Fail -> leak suspect: the smaps
  breakdown names the part ([heap] / other anon / pool) for the follow-up.
- LIGHT 2 memory: quiet-window anon+kernel+sock and 30-min-minima anon slopes, ESTAB covariate, with CIs; FAIL if the
  minima slope CI lower bound > 1 %/h of the floor. Host TCP: TcpExt TCPMemoryPressures delta 0 (VPS3 is the
  user's box; raise --gap-scale if the first 30 min show any).
- HEAVY: as above for crashes, errors, fds/threads; RSS / smaps anon floor at the quiet windows: minima slope CI lower
  bound < 1 %/h; memory level changes allowed only with a recorded host/cgroup cause.
- Watch (report, not fail): pool_release_max_us and pool_release_cpu_max_us (wall vs CPU: a wall >> CPU gap = scheduling,
  30.14 watch 2); kTLS starve episodes; canary p99 under saturation.

## Heavy lane: B with a budget (lead, 2026-10-30; commit 31d317c)
- `--mem-budget-b SIZE` gives server B `--mem-budget SIZE`; A stays unbudgeted (MemTotal/2) as the control. Without
  a cgroup the budget's usage = B's heap + HOST TCP memory above its startup baseline (mem.rs Source::Host), so B's
  level follows the whole box's socket memory (A + clients + targets), not only its own: a shared-host case on purpose.
- Sizing from the K 25 smokes (B unbudgeted, smoke2: usage median 39 MiB, p90 152, p99/max 4.9 GiB):
  - 1536M (smoke5, 15 min): 12 episodes, peak level 3 in 10 of them (L3 at 1,306 MiB; heap only 40-330 MiB, the rest
    host TCP): too tight (L3 most of the time it moves).
  - **6G (smoke6, 15 min): 5 episodes, 4 x L1 only, 1 x up to L3 (19 s); 82 level changes; B refused 29 M CONNECTs
    with 0x49 at L2+ (refuse_admit), shed 58 clients, 2 pend; back at level 0 at the end. Chosen.**
  - Both smokes: 26 PASS / 0 FAIL (re-analyzed after review rounds 1-2, three reviewers; commits d4f61a6 + next).
  - Analyzer: B's level episodes from both ends of the logged "memory level" lines, the metrics line's level gauge
    (soak.py `level_gauge` events, every 10 s) and B restarts; an unlogged L2 visit is inferred from the "k changes
    not logged" count. A B run or probe that fails while an episode of **peak >= 2** overlaps it (+-30 s) is
    "degraded" (shown) only if every printed error is on a strict allowlist: 0x49 closes, WS close 1013, connection
    reset / EOF / broken pipe, and the timeouts of paused admission (L2+); upload stalls only at L3. At L1 nothing may
    fail; any other reason, a verify error, wrong bytes or a reasonless failure stays a FAIL.
  - wbench `error_kinds` (bench/src/errkind.rs, lead OK 2026-10-30): every counted error has one key (stream_0xNN,
    conn_close_0xNN, ws_N, errno_N, setup/handshake timeout, timeout, eof, upgrade, tls, proto, join_timeout, other),
    summing to `errors`; the first-8 text stays. With it the analyzer checks every error of a degraded run (sum ==
    errors, keys in WB_OK_KINDS); the text check remains only for an older wbench.
  - Level-0 budget sheds (smoke8): B's pend_sweep closes the largest upload backlogs with 0x49 at any level once a
    worker's backlog is over pend_cap (the budget's share; worker.rs "at every level"). A B run whose only errors are
    stream 0x49 closes is accepted when B's shed counters (shed_pend + shed_hold, both read at both ends) rose by at
    least that many over the run, same generation. Negative check: one close more than the counters -> FAIL.
  - Smoke8 (6G; the smoke ran wbench md5 56c46f1e, final after review 3: de746df6, classify order only): 26 PASS; B error kinds ws_1013 21,
    stream_0x49 4.
  - Expectations: transitions happened; B at level 0 by its last metrics line; A level changes INFO (0).
  - `--mem-budget-b` requires `--no-scope` (the scope's MemoryMax=1G would OOM B first).
- Observation for the mem.rs owner (not a harness issue, not judged here): in host mode B's level flaps 0 <-> 1 for
  10-30 s when the usage sits at the level-1 exit (smoke5: ~100 "1 -> 0 ... 1 changes not logged" at 600-613 MiB vs
  exit 614; smoke6: 36 at 2,443-2,456 MiB vs exit 2,458). Changes to 0 are always logged, to 1 rate-limited, so each line
  is one 0 -> 1 -> 0 pair. Usage = heap + host TCP pages, and A's bursts move host TCP by GiBs in seconds, so this may
  be real swings at the DWELL_DOWN rate; each flap internal notes (not published) sockets. Worth a look in the mem.rs round.
