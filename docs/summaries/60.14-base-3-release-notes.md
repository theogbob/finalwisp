# 60.14 base-3 release notes (2026-10-28)

Pointers: 60.13 (default-on decision + evidence), 60.12 (plan), 20.30 (credit v2), 20.31 (B3 tcpmem adapt), 20.26 (memory
levels), 40.01 (deployment), 40.02 (CI + reproducible build), 70.09/70.10 (own DNS), 60.10 (base-2).
Tag base-3 = merge of b3-optin 4097cb1 (option A of 60.13's outcome). Release binary: bench/release.sh, md5
55d175ae7d73f2f2702863f210a9140b (path-independent since 40.02). Clean-lane reference build (release.yml on the tag,
fresh VM, task 79, artifact finalwisp-6de8b4f…): md5 55d175ae, identical; fast-lane ci.yml on the tag: identical too.

## On by default (new)
- Upload credit v2 (20.30): a WS ping after each CONTINUE batch retires old credit; per-stream windows autotune (1-56 MiB)
  and shrink when a target stalls (streams with siblings); state created lazily (idle/download-only streams cost nothing).
  Off: --no-credit-v2 (= base-2 credit rule).
## Fixes (always on)
- Memory level 2/3: keep 132 KiB (every drained obuf was freed and regrown); target socket cap 16 -> 32 KiB (kernel 6.17+
  dropped loopback segments at 16 KiB: echo stalls to RTO).
- SIGINT ignored at startup stays ignored (nohup / `cmd &`); SIGTERM always drains.
## New, opt-in or operational
- Host TCP-memory adaptation, B3 (20.31), opt-in --tcpmem-adapt: near net.ipv4.tcp_mem pressure, this server's sockets take
  the level-1 caps and credit. Trades CPU for memory: on 2-vCPU loopback under pressure bulk downloads ran 0.65-0.83 at ~2.8x
  CPU/MiB while echo ran 1.5-2.9x with 2-3x lower peaks. Needs credit v2 (refused with --no-credit-v2: B3 alone moved credit
  into the heap, upload 0.36x / 201 MiB), cgroup v2 memory accounting (own share >= 1/4), SO_BUF_LOCK (5.15+) and the host
  netns; the startup line says when/why it is off. --no-tcpmem-adapt is accepted (no-op). Redesign in progress (b3-redesign).
- Graceful drain on SIGTERM/SIGINT (--drain-timeout, default 30 s); contrib/finalwisp.service; deployment doc 40.01.
- Metrics line (--metrics-interval SECS, off by default; counters at control points only).
- Own DNS resolver (--dns-own) + RFC 8305 late family delivery (v4-only 52 ms instead of 4.0 s).
- KeyUpdate on kernels < 6.14: one rate-limited log line + counter (who rekeys: native rustls after 2^24 AES-GCM records;
  browsers in practice never, source-verified).
- Tooling: wst "tie" needs the 90% CI within 5% (else "unclear"); proxy compat step (nginx, Caddy); Forgejo CI (fast lane
  every push, clean-lane reference build on tags); reproducible release (laptop = container = CI md5).

## Known limits / costs
- With one stream's target stalled, a sibling stream on the same connection gets 0.68 of its rate (base-2 0.83); totals equal.
- One upload stream to a fast target: 2.5-4.4% slower (inside the 0.95 bar).
- Echo memory.peak 0.76 of base-2 under v2 (bar was 0.70; the rest is kernel socket memory).
- B3 (opt-in) is off in containers with their own netns, cgroup v1, kernels < 5.15; a forced early TCP level moves the first
  level-0 grant into the heap (114-130 MiB on loopback with a 70% holder).
- 16 MiB budget L1<->L2 flapping (pre-existing; deferred); KeyUpdate < 6.14 closes the connection.
