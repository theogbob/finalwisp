## Cause
Driver pd.py: the server in a user scope like potato (MemoryMax N MiB, no swap, 1 CPU, --threads 1), wbench download 10x10
16 KiB, 2 s, strace -f (counts only, no throughput claims). The server is at level 1 the whole run at 32/64/128M (small budget).
Per run (mmap+munmap+mremap): base-1.1 67-70; base2 640-1520. Sizes (base2, 32M): mmap 69632 x232, mremap 69632->135168 x232,
135168->266240 x232, 266240->528384 x220, munmap 528384 x219. Stacks: realloc from read_target's reserve(ROOM_WISP + CHUNK).
So: the bulk lane (download = bulk mode) grows by Vec doubling from 65539: capacity 524312, 24 bytes above STAGES[1].keep
(512 KiB), and flush frees a drained lane with capacity > keep at every drain. base-1.1 did the same free, but in the glibc
arena (1 MiB threshold): no syscall. With base2's 16 KiB threshold each cycle = mmap + 3 mremap + munmap + ~128 page faults.
The block cache does not help (it keeps 16-132 KiB). Not rbuf, pend or pipes (pipe2 10 per run in all builds).
A slack of one read on keep (variant tried, not kept): a model of read_target (out_high 256K + its compaction rule
`ohead >= len - ohead`) reaches capacity 1048624, so the free would come back.

## Fix (4ce741e)
free_drained(level, cap, keep): L0 never (as before), L1 only cap >= 4 x keep (2 MiB: above L1's own growth <= 1048624; a lane
grown at L0 to 2-4 MiB that was not drained when L1 started is still freed at its first drain: review), L2+ cap > keep (as before).
Only the two flush drain sites change; set_level's one-time drop (when keep shrinks), pend/rbuf rules, idle sweep unchanged.
Test drained_buffers_freed_by_level (capacities 65539..8 MiB at each level).

## Review (three reviewers; reviewer C 402)
Reviewer A: P2 L0-grown lanes kept at L1 while active (fixed: 4 x keep), P3 doc (set_level drops only when keep shrinks; fixed);
answered: peak unchanged (a kept lane is never larger than the live one; only touched pages are resident), splice, bulk_drop
invariants, cache, set_level all fine; possible L1<->L2 flapping at 16M only measurable on the VPS. Reviewer B: no defect; same note
that an L0 lane not drained at the transition keeps its capacity (now fixed); 16M: retained capacity is detected by the sampler,
no hard OOM guarantee (unchanged in kind).
