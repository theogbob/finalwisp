# 60.32 C6 upstream proxy: as built (60.20 wave 3, 60.18 #17)

Research and pre-spec: 60.27 (wispurr survey, parity table, the raw proxy probe, the disassembly method, two
design reviews; prototype and evidence on a research branch (not published)). Decisions: 60.02 Q1 / Q1b, 60.18 #17
(socks5:// and http:// in v1; https:// refused at startup; socks5h:// only with --upstream-trust-dns; the 60.27 picks
C 30 s refresh thread, D no auth file, E finer codes, F 4 tries one deadline; every unsupported form fails loudly).
Code: `server/src/upstream.rs` (URL, ProxyAddrs + the `upstream-dns` thread, request bytes, pure reply parsers),
`server/src/worker/upstream.rs` (the per-stream state machine), hooks in `worker/connect.rs` (new_target,
start_connect, inbox_ready's r.more guard, try_connect, won), `worker/target.rs` (Target::in_handshake, target_event,

SECRET_FLAGS, check), `main.rs` (resolve, warnings, capability note), `net.rs` (start_dns_pool `early_on`), `metrics.rs` /
`prom.rs` (counters, refresh health). Operations: 40.01 "Upstream proxy"; flags: 40.03 "Upstream proxy".
Branch c6-upstream from master d3abe65; merged into master in 9e9741e (in base-6-rc1, 60.33).

## Decisions as built
1. Flags `--upstream URL` and `--upstream-trust-dns`, both `--config` keys. URL: `socks5://`, `socks5h://`, `http://`
   (scheme case-insensitive), optional `USER[:PASS]@` (percent-decoded, 1-255 bytes each; an HTTP Basic user without
   `:`), host = name, IPv4 or `[IPv6]`, optional port (default 1080 / 80); no path, query or fragment. `parse_args`
   checks the syntax (`upstream::parse_url`), `cli::check` the cross-flag rule (`upstream::check_trust`: socks5h needs
   --upstream-trust-dns, the flag needs socks5h). Refused at startup, exit 2: `https://` ("not supported; use http:// or
   socks5://"), other schemes, an unbracketed IPv6 address ("goes in brackets"), port 0, bad %-escapes, lengths. A proxy
   name with no address: exit 1. Every parse_url error is a fixed text (no part of the URL in it).
2. Secrets (C8): `--upstream` is the first SECRET_FLAGS entry (a group/world-readable --config that holds it: warning).
   Credentials on argv: warning (/proc/PID/cmdline). Credentials at all: warning (clear text to the proxy). The URL is
   shown as `scheme://***@host:port` (`Upstream::shown`, also its Debug); `Expanded` has a Debug that hides `args`;
   `utf8_args` and an unknown non-flag argument no longer echo the value (a mistyped `--upstream=URL`).
3. Implied with an upstream: UDP off (Q1b: `cfg.udp = false`, so the existing --no-udp refusal gives 0x48 and the UDP
   extension is not advertised), TFO off, --dns-own early answers off (`start_dns_pool(.., early_on = false)` plus a guard
   in inbox_ready: `dns_late` would mix target and proxy addresses).
4. The proxy's addresses (`upstream::ProxyAddrs`): resolved at startup with getaddrinfo (search list allowed: the
   operator's name), deduplicated, families interleaved. A name gets the `upstream-dns` thread (60.27 Q-C): every 30 s
   resolve and publish an immutable `Arc<Vec<IpAddr>>` under a Mutex with an AtomicU64 generation (a new generation only
   when the list changed). A failure or an empty answer keeps the last list (never direct egress) and counts. Workers
   compare the generation (one Acquire load per proxied connect) and take the lock only when it moved
   (`Worker::proxy_list`); no wake-up. No thread for an IP literal or without --upstream. Health in the metrics line
   (`upstream_dns_fail`, `upstream_dns_age_s`) and /metrics (`upstream_dns_fail_total`, `upstream_dns_age_seconds`),
   only for a proxy by name. The proxy address itself is not checked by the address rules (the operator's choice).
5. State machine, no new TState (a 4th variant made target_event's dispatch a jump table, 60.27):
   Resolving (local DNS + C1 rules, unchanged) -> Connecting with fd -1 (Happy Eyeballs over the proxy's addresses with
   the unchanged try_connect / connect_progress / won) -> handshake = Connecting with fd >= 0
   (`Target::in_handshake`; conn and addrs empty, listed in `connecting`) -> Open (`connected()`, unchanged: splice,
   kTLS, upload batching). `won` applies C10a upload pacing to the proxy socket first, then `proxy_begin`.
   Replies are read with MSG_PEEK and only their exact length is consumed: tunnel bytes stay in the socket for
   read_target / splice. `proxy_event` (cold, not inlined) runs before the Connecting event mask (an EPOLLIN-only event
   is a reply), records a FIN that came with the reply (`peer_closed`), and reads tunnel bytes once after Open.
   A hangup with an incomplete reply counts only when `peer_closed` confirms it on this fd (the epoll token is shared
   with the HE attempts). EINTR on send / recv retries (review).
6. Side entry `Worker::proxy_hs[ti]` (Target and Client unchanged): created by proxy_start / proxy_name, dropped just
   before `connected()` and in `close_target` (every other exit: client CLOSE, client gone, deadline, failure, drain).
7. Deadline: one --connect-timeout for the whole open (proxy connect, handshake, the proxy's own connect, retries).
   try_connect refuses a new proxy connection past it; run_timers ends a handshake at it (0x43). Both count
   `upstream_fail`, as does every proxy address failing (review: the SYN-blackhole case was uncounted).
8. CLOSE reasons (60.27 table): SOCKS REP 02 / HTTP 403 = 0x48; REP 03, 04 = 0x42; REP 05 = 0x44; REP 06 / HTTP 504 =
   0x43; the proxy unreachable = the connect errno's code (refused 0x44, wispurr parity); auth refused, bad replies,
   other codes, a head over 8 KiB = 0x03. Retry (60.27 Q-F): a refusal about the target (REP 03-06, HTTP 500/502/503/504)
   tries the next target address (IPv4 first) over a new proxy connection: at most `PROXY_TRIES` = 4 addresses, within
   the deadline, local DNS only; the stream keeps its admission, token and queued upload. `upstream_fail` = the proxy
   itself failed (not a refusal about the target).
9. socks5h + --upstream-trust-dns: names go to the proxy (ATYP 3) as absolute names (`name.`, 60.18 #16; > 255 bytes
   after the dot: 0x42), except RFC 7686 `.onion` names (any case), which go without the added dot (base-6 RC2 fix:
   Tor refuses `x.onion.` with REP 04, so every onion service was 0x42; `upstream::proxy_name`). The policy and the C1
   rules see the same name as before (the client's one trailing dot removed). Other proxy-only TLDs (`.i2p`, `.exit`)
   keep the dot; add them to proxy_name if a site needs them. Still enforced: the request rules, IP literals (every address rule), no inet_aton forms (0x48),
   no loopback names without --allow-loopback (`localhost`, `*.localhost`, `localhost.localdomain`, `localhost6`,
   `localhost6.localdomain6`, `ip6-localhost`, `ip6-loopback`), LDH + `_` only (0x41). Not enforceable for names: the
   address classes, own addresses, --allow-dest / --block-dest, --no-ipv6-targets, other /etc/hosts names on the proxy.
10. Stats appended last: `upstream_ok`, `upstream_fail` (after `pace_fail`).

## Default changes (C6 off)
- None in behaviour: no thread, no socket, no setsockopt; Config grows one pointer (`upstream: None`), Worker two
  empty fields; Target and Client unchanged.
- Visible: `--help` gains the "upstream proxy" line; the metrics line gains `upstream_ok=0 upstream_fail=0` after
  `pace_fail`; two argument errors no longer quote the argument: a non-UTF-8 argument ("an argument is not valid
  UTF-8") and an unknown argument that is not flag-shaped ("unknown argument (not shown: not a flag name; it may hold a
  secret)"); a flag-shaped unknown argument is still quoted.

## Review (review: reviewer B, reviewer A)
- Both: upstream_fail was not counted when the proxy never answered the SYN (deadline with fd -1). Fixed (decision 7),
  with a worker test case.
- Reviewer B: the worker test's `read().unwrap_or(0)` let a read timeout pass as "closed": now only EOF or a reset passes.
  upstream_real.py now exits 1 on a failure.
- Reviewer A: EINTR on the handshake send / recv: retried. Checked and not changed: `t.moved` reset on a retry (lazy_cap
  counts only on Open paths, so it is 0 during the handshake); `Upstream`'s pub credential fields (nothing prints them;
  no derived Debug); `peer_closed` polls POLLRDHUP, so a partial reply + FIN fails at once, not at the deadline.

## Release-note lines (60.33)
- C6 upstream proxy (off by default): `--upstream socks5://|socks5h://|http://[USER:PASS@]HOST[:PORT]` sends every TCP
  stream through one proxy; DNS and the destination policy stay local; UDP refused (0x48) with an upstream; `https://`
  refused at startup; socks5h needs `--upstream-trust-dns`. Metrics `upstream_ok`, `upstream_fail` (+ refresh health
  for a proxy by name). Default-visible: --help line, two metric keys, two argument errors that no longer echo the value.
