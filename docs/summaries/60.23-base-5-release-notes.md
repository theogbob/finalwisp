## Default changes (behaviour without any new flag)
- **Own interface addresses are blocked as targets** (C1, 60.21), also with --allow-private. The set is read once at
  startup with getifaddrs (loopback-class addresses excluded). `--allow-self` restores base-4 behaviour.
- **IPv6 forms that embed an IPv4 address are blocked as targets** (C1): `::/96`, 6to4, Teredo, local-use NAT64. Also
  with --allow-private. `--allow-embedded-v4` restores base-4 behaviour. `0.0.0.0/8` and `::` stay in the loopback
  class (unchanged).
- **Two more IPv6 ranges are private** (C1): `fec0::/10` (old site-local) and `100::/64` (discard). They need
  --allow-private (or --allow-dest) like the other private ranges.
- **NAT64 well-known prefix** `64:ff9b::/96` and `::ffff:0:0/96`: judged by the IPv4 address they carry (a public IPv4
  is allowed, a private one needs --allow-private, a blocked IPv4 stays blocked in this form). Decided by the maintainer
  (60.18 #15, option A): IPv6-only hosts with DNS64 reach every IPv4 target in this form, so a hard block of the
  prefix would break them. One constant, net.rs `NAT64_WKP_BY_V4` (true).
- **Client host names are resolved as absolute names** (60.18 #16, branch dns-abs): getaddrinfo gets `name.`;
  --dns-own asks the name only. The resolv.conf `search` / `domain` / `ndots` settings are no longer applied to client
  names, so `--block-host` sees the name that is resolved. A short internal name (`wiki` meaning
  `wiki.corp.example`) now gets 0x42 unless it is in /etc/hosts (looked up first, both resolvers) or sent in full.
  A name with two trailing dots (`a.com..`) gets 0x42 without a lookup. Coverage: --dns-own end to end (compat
  dns-own, a private resolv.conf with `search` + `ndots:5`); the getaddrinfo path by unit tests of the name it is given
  (`name.`; only numeric forms glibc converts stay as sent) and by the Docker check.
  Docker check (functional, laptop, two containers on a user network, both resolvers): a container name, the same
  name with a trailing dot or in capitals, and an `--add-host` alias all connect; an unknown name gets 0x42. `a.com`
  and `a.com.` share one DNS cache entry and one in-flight lookup.
- **Startup stops if the interface addresses cannot be read** (C1 review fix: fail closed). getifaddrs failure: a message
  and exit 1, unless `--allow-self` (then no own-address check).
- **`--no-udp` refuses UDP streams with 0x48** (blocked; C1 = Q7). base-4 sent 0x41 (invalid).
- **Malformed host: 0x41** (C1). A CONNECT whose host is over 255 bytes, or holds a NUL, a control character, a space
  or DEL gets 0x41 at once. base-4 sent 0x42 (over-long names at once, the others after a failed lookup). An empty host
  got 0x41 already (unchanged). wsproxy answers such a target with 400.
- **SMTP hint at startup** (C1, Q3): a default start prints
  `finalwisp: hint: mail ports 25/465/587 are open to clients; --block-smtp closes them`. It is a hint, not a block.
  It does not print with --block-smtp, or when the TCP port rules block all three ports.
- The capability line gets new fields only when a feature is on: `config FILE`, `limits: ...`, `policy: ...`,
  `client ip: ...` / `per-ip: ...`. On a default start it shows `policy: own addresses blocked (N)` (40.01 table).

## Upgrade notes (from base-4)
- **No flag was removed or renamed** (40.03 --help of base-4 vs master: 0 flags gone, 18 new). A base-4 start command
  runs unchanged.
- **The build without the own allocator is gone** (60.18 #11). `NOFEAT=1 bench/release.sh` and
  `FEATURES=own-alloc` are refused. Build tag base-4 if you need the old allocator path.
- Check the default changes above:
  - A client that connects through finalwisp to the server's own public address (for example a nested Wisp, or a web
    page on the same host) now gets 0x48. Add `--allow-self`, or `--allow-dest ADDR` for one address.
  - A 1:1 NAT or elastic IP address is not an interface address, so it is not in the own set. Block it with
    `--block-dest` (Known limits).
  - Clients that test for 0x41 on `--no-udp` must accept 0x48.
  - Clients that rely on the server's resolv.conf search list (a bare `wiki` for `wiki.corp.example`) must send the
    full name, or the name goes into /etc/hosts.
- Behind a reverse proxy, per-IP limits need `--trusted-proxy` (40.01 "Reverse proxy"). Without it every client has the
  proxy's address and all share one limit.
- Metrics lines have new keys: refuse_limit and refuse_conns (C3a, placed before dns_hit), conns_reserved and
  conns_max (C3a, after conns, only with --max-conns), refuse_policy (C1), refuse_ip_conns, refuse_ip_rate, realip_bad,
  realip_missing, ip_untracked, ip_keys_max (C2 + C3b). No key was removed or renamed; a parser that reads keys by name
  needs no change, one that reads by position does.

## What is new since base-4 (tag base-4, code 1f01089, md5 6b7a1c30)
- **C8 `--config FILE`** (60.20 W1 step 1; 40.03): a flag file, expanded into argv at its place, so one parser checks
  everything. One `flag value` per line, `#` comments. Flags after --config override the file; a list flag on the
  command line replaces the file's list. Errors exit 2 before any socket and never show a value. A bad line gives
  FILE:LINE and the flag; a file that cannot be read, or a check across lines (4 DNS servers, an unpaired TLS flag),
  names the file only.
- **C3a global limits** (60.20 W1 step 2; 40.03):
  - `--max-conns N`: an exact process-wide count, taken right after accept4 and before TLS. Over the limit: TCP RST.
  - `--max-streams-per-conn N`: over the limit a CONNECT gets 0x49; the connection stays open.
- **C1 destination policy** (60.20 W1 step 3; 60.21; 40.03 "Destination policy"):
  - Request rules run before the stream cap, memory admission and DNS, so a refused CONNECT costs no slot, budget or
    lookup: `--allow-ports` / `--block-ports` (tcp:/udp:), `--allow-host` / `--block-host` (suffix match),
    `--no-direct-ip`, `--block-smtp`, and `--no-ipv6-targets` (also: no AAAA query).
  - Address rules run on every resolved address: `--block-dest` / `--allow-dest` (CIDR lists), and the classes
    (loopback, private, own, embedded IPv4) with `--allow-self` and `--allow-embedded-v4`.
  - Refusal: 0x48. wsproxy: a request rule gives 403 before the 101; an address refused after DNS closes the
    WebSocket (1000) after the 101.
- **C2 real client IP + C3b per-IP limits** (60.20 W1 step 4; 60.22; 40.03 "Client IP and per-IP limits"):
  - `--trusted-proxy CIDRS` / `--real-ip-header NAME` (default x-forwarded-for, walked right to left, trusted hops
    skipped).
  - `--max-conns-per-ip N`: direct peers over the limit get an RST at accept; behind a trusted proxy, 429.
  - `--stream-rate-per-ip R[/B]`: a token bucket per client; empty: 0x49 (wsproxy: 429).
  - Keys: IPv4 address, IPv6 /64. The table holds at most 65,536 keys (Known limits).
- **Old allocator path removed** (60.18 #11; merge 982b8cd): the 70.11 block cache and the `--no-default-features`
  build are gone; CI and compat lose their nofeat lanes. The default build has the same normalized disassembly as
  base-4 (bench/tools/disasm_norm.py).

## Known limits
- **CNAME targets are not checked by host rules** (60.21): `--block-host` sees the name the client sent; the address
  rules still apply to every resolved address. (The search-list gap of the C1 build is fixed: absolute names, above.)
- **1:1 NAT and elastic IP addresses are not in the own set** (C1): they are not interface addresses. Use --block-dest.
  The own set is a startup snapshot; an address added later is not in it (60.18 #13 c).
- **Trusted-proxy window before HTTP** (C2): a connection from a trusted proxy is charged per IP only after its HTTP
  request. Until then only --max-conns and the handshake timeouts bound it.
- **The per-IP table fails open when full** (C3b, Q11): at 1024 keys in a shard a new key is not tracked or limited
  (metric ip_untracked); --max-conns stays the backstop. A trusted proxy with no header is not limited per IP
  (realip_missing).
- **Every address inside --trusted-proxy may name any client**: list only the proxies, not a range that also holds
  clients (40.01).
- **IDN host names are matched as sent** (punycode); finalwisp does no IDNA mapping (C1, 40.01).
- **RFC 7239 `Forwarded` is not supported**; X-Forwarded-For or one single-value header only (C2, 40.01).
- From base-4, unchanged: 60.19 Known limits.
