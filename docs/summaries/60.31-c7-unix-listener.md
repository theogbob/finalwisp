## Decisions as built
1. `--listen-unix PATH` adds a second listener; the TCP one stays (Q8). `--unix-mode OCTAL` (octal digits only, <= 777,
   default 660; alone = exit 2). Both are --config keys (FLAGS table). Plain ws:// only (Q7): adopt builds no TLS state
   for a unix fd even with --tls-cert.
2. One listening fd for all workers (AF_UNIX has no SO_REUSEPORT groups), SOCK_NONBLOCK (a worker that loses the race
   gets EAGAIN), in every worker's epoll with EPOLLIN|EPOLLET|EPOLLEXCLUSIVE under token K_LISTEN index 1 (the TCP
   listener is index 0); before Linux 4.5 EPOLLEXCLUSIVE is EINVAL and a plain registration is used.
3. Forced hand-over (Q2): EPOLLEXCLUSIVE wakes the first idle waiter in registration order, so without it 40 of 40
   accepts landed on one worker (60.28). `route` (conn.rs) is the old --balance block made a function: it runs for
   every unix accept and, with --balance, for TCP ones; Inbox.load is counted once, on the final owner (fold-in). Compat:
   40 clients -> 10/10/10/10 per worker epoll (counted from /proc/PID/fdinfo, no strace).
4. Startup (`net::listen_unix`, called by main before any thread exists, so the process-wide umask is safe):
   `PATH.lock` (0600, O_NOFOLLOW, never removed) flocked LOCK_EX|LOCK_NB for the life of the process (Q10): a second
   finalwisp on the path exits 1 ("another finalwisp holds this path"); then an existing path: not a socket = exit 1
   (left alone); a non-blocking connect() to it succeeds or gets EAGAIN = a live server (exit 1); ECONNREFUSED =
   leftover, removed (known limit, review: a socket another program has bound but not yet listen()ed on looks the same;
   40.01 says to use a path no other program uses); then socket, bind under umask(!mode & 0777) (the file gets exactly
   the mode; no chmod, which would follow a symlink swapped in; the old umask restored right after bind), listen(4096).
   Path over 107 bytes or with NUL: exit 1. The bind happens before the TCP port check: a later startup failure leaves a
   socket file that the next start replaces.
5. Shutdown: each worker's shutdown_step accepts what is queued, then EPOLL_CTL_DEL of the shared fd from its own epoll
   (debug_assert that it was there), then `UnixListen::release`: an atomic count of holders; the last one unlinks the
   path only if (dev, ino) is still the file it bound (a newer instance may own the path), then closes the fd (unlink
   before close: 60.28 review). `inbox.stopped` is set after that, so main's exit implies the file is gone.
6. Identity: a unix client's peer is `clientip::UNIX_PEER` = `100::` (RFC 6666 discard-only, never a real TCP peer;
   its /64 key is nobody's, unlike `::`). `--listen-unix` forces a ClientIp whose trusted list is --trusted-proxy plus
   `100::/128` (main::build_clientip, built from the const). So the unix peer's --real-ip-header is read and charged at
   the upgrade (Q3); no header = not charged (realip_missing); unparsable = the shared sentinel key (fail safe, 60.22).
   The "N trusted proxies" note counts only --trusted-proxy.
7. tcp_peer split (fold-in): `Config::want_peer` (TCP accept4 asks for the sockaddr) does not count --listen-unix:
   only C2/C3b flags or --log-conns. A unix accept never asks (the peer is the sentinel). adopt writes a peers_of entry
   for every client when --listen-unix is on (TCP clients without want_peer get None: a slot can never show a TCP client
   a former unix client's trusted peer; close_client takes every entry anyway). Worker::new's want_peer assertion
   accepts the sentinel-only ClientIp.
8. Sentinel guard (fold-in): with --listen-unix, a TCP peer whose address is exactly `100::` is reset at accept (RST,
   the --max-conns reservation released, metric refuse_sentinel). It runs where the sockaddr is read, i.e. with
   want_peer; without it no TCP client gets a Peer, so it cannot be trusted either.
9. `Client::local = LOCAL_UNIX (3)` (target.rs): no TCP_NODELAY / --notsent-lowat at accept; never capped at memory
   level 0 (the two client cap sites test it before tcp_only_local; levels 1+ cap it like any client); no dead-peer
   probe (TCP_INFO) and no stall shed (60.20 user f, documented in 40.01) in the sweep. kTLS never (no TLS). The
   download still splices into it (compat: 657 splice calls for 64 MiB). --download-rate cannot pace a unix socket: a
   startup warning (not an error: the TCP clients are still capped).
10. No credit_pong arm (fold-in, Q1 of 60.28): the per-pong TCP_INFO min_rtt getsockopt fails on a unix fd and the
    ping RTT is used; one failed syscall per pong for unix clients, no new branch in that path.
11. Load-bearing invariant (60.28): the accept charge skips trusted peers, so `client_ip`'s `p.key = Some(k)` never
    overwrites a key. `debug_assert!(p.key.is_none())` there (upgrade.rs). Mutation (charge trusted peers too): the
    unix worker test fails (and the C2 trusted-proxy test), release and debug builds.
12. Logging (C4): `ip=unix` for the sentinel (connlog::ip_value), `ip=<client> via=unix` when its header named the
    client, `ev=conn_refused ip=unix why=limit` for a --max-conns refusal on the unix socket. TCP_INFO byte counts
    (rx/tx) are absent on unix lines.
13. Metrics (appended last in Stats): accepted_unix (also counted in accepted), refuse_sentinel. Startup: a separate
    info line `finalwisp listening on unix:PATH (ws://, mode 660; its peers' client-IP header is believed)`; the
    capability line is unchanged.
14. "Read to the blank line" (60.28 C5 fold-in) does not apply here: C7 adds no HTTP parsing.
