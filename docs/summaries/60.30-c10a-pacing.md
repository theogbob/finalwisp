## Decisions as built
1. Flags `--download-rate RATE` (per client connection) and `--upload-rate-per-stream RATE` (per TCP target), both
   `--config` keys (FLAGS table). Names: the 60.25 family (a research branch (not published): `--download-rate`; `--upload-rate` / `--upload-rate-per-ip` are its
   C10b upload totals);
   60.26 had proposed `--download-rate-per-conn`, shortened to match 60.25. RATE = bytes/s, parse_size grammar
   (plain or K/M/G = KiB/MiB/GiB), 0 = off, else 16K..4095M (MIN_RATE: the 16 KiB lowat floor, fq's 10 s horizon and the
   10 s kTLS linger stop holding below it; MAX_RATE: the kernel's u32 option, never its 0xFFFFFFFF "no limit").
2. Download: SO_MAX_PACING_RATE on every worker listener, after keepalive and before bind/listen (children already
   queued would miss a later setting). Accepted sockets inherit it (sk_clone -> sock_copy copies sk_max_pacing_rate,
   sk_pacing_rate, sk_pacing_status), so accept_all / adopt have no new code and `--balance` hand-offs keep it. A refused
   setsockopt on a listener fails startup with the reason.
3. Startup self-check (main::check_pacing -> net::pacing_inherited): a loopback listener with the rate, a non-blocking
   connect, poll <= 1 s, accept, getsockopt on the accepted fd. All three fds are OwnedFd (closed on every path).
   Some(false) (refused, or another value) = refuse to start; None (no 127.0.0.1, ...) = a warning, the cap stays set but
   unverified. It proves inheritance only, not that every route enforces the rate (60.26 [rt2]).
4. With a download cap (Pacing::client_settings): splice off for the process (60.18 #17; 60.26: a binding cap split 4 wss
   streams 0.24-0.43 min/max with splice, 0.93 without) and the client TCP_NOTSENT_LOWAT = min(--notsent-lowat,
   max(16 KiB, RATE/8)) (~125 ms of queue at the cap, a queue bound, not a latency bound); `--notsent-lowat 0` (kernel
   default) stays 0. The 20.21 adaptive lowat does not sample capped clients when the cap is below LOWAT_FAST (1 GiB/s):
   a delivery-rate sample excludes pacing gaps and could exceed the cap and lift the lowat to INT_MAX (review).
   Config::adapt_lowat (worker::adapt_lowat, computed once in main: the lowat, or 0 under such a cap) replaces
   `notsent_lowat` in flush_dirty's test, so the hot path has the same instructions.
5. Upload: in `won`, first thing (before the Happy Eyeballs memory: a stream that fails here teaches it nothing),
   SO_MAX_PACING_RATE and TCP_NOTSENT_LOWAT max(16 KiB, RATE/8) on the winning fd, both checked
   (net::try_notsent_lowat; net::set_notsent_lowat stays best effort for the client side). Either refused: metric
   pace_fail, `fail_target(ti, 0x03)`, return. That exit is the normal close of a Connecting target: the fd is still in
   t.conn (close_target closes it), unlist, pend released by its acct, CLOSE 0x03 to the client (review checked it).
   TFO SYN data (at most one MSS, a ClientHello) leaves before the cap, within the 10 unpaced segments anyway. UDP
   targets are not touched (U4). With C6 the winning fd will be the proxy connection: its handshake bytes count.
6. No release helper: nothing is counted or taken; the settings die with the socket.
7. Capability line: `, pacing: download/conn R B/s = X Mbit/s (splice off) upload/stream R B/s = X Mbit/s (TCP streams
   only)`, only the set parts; `(splice off)` only when splice was not already off by --no-splice.
8. Metric pace_fail appended last (no hot offset moves).

## Tests
Unit: cli `pacing_rates` (grammar, bounds, errors, --config form, command line after --config overrides); net
`paced_lowat_rule` (derivation, client_settings: splice/lowat), `pacing_inherited_by_accepted_sockets` (listen with a
rate -> the accepted socket has it; off = u32::MAX; a per-socket value overrides; fd -1 errors). Worker
`pacing_caps_on_clients_and_targets`: a `--balance` hand-over keeps the listener's cap on the adopted client; `won`
puts the cap and the lowat on the target; off: no cap; fail closed (test hook PACE_REFUSE, cfg(test) only): CLOSE 0x03,
pace_fail, the stream removed, the attempt's fd closed. Fuzz: `cli-parse` knows both flags and asserts every accepted
rate is 0 or in range. Compat step `pacing` (tests/compat/pacing.py, base+78/79, loopback, no root; band 0.8..1.25 x
cap): download 1 stream, 3 clients with --threads 2 --balance, 2 upload streams each at the cap, uncapped > 5 x cap, the
startup line, bad values refused, the --config form. The netns + veth + qdisc matrix stays a research script (60.26,
needs root).

Compat gate (`bench/wst compat --matrix --fuzz-replay --base-port 13600`, laptop, functional only): 44/44 PASS
(35 in the first run; the 9 wispjs/tls steps failed only because the new worktree had no tests/compat/node_modules,
then passed on rerun with it linked). Logs: raw data (not published) pacing step: download

## Review (reviewer B, reviewer A; reviewer C unavailable: 402)
Fixed: adaptive lowat could lift the paced client lowat (reviewer B P2, decision 4); fail-closed path untested (reviewer B P3: the
PACE_REFUSE hook and assertions); two listener fds leaked by the worker test (reviewer B P3); the HE memory was updated before
the fail-closed exit (reviewer A P2: the hook moved first); the splice/lowat derivation was only checked by compat (reviewer A P2:
Pacing::client_settings + a unit test); a refused option on the self-check's listener said "could not run" (reviewer A P3:
now Some(false), refuse to start); the compat step read the log after a fixed sleep (reviewer A P3: waits for the
capability line). Not changed: `rate()` takes a leading `+` (parse_size, pre-existing; harmless).
Round 2 (reviewer B, reviewer A; both on the delta): the fail-closed test checked the closed fd by number (racy with other test
threads) and its pend check was vacuous: now the target peer must see EOF and the queued upload is accounted
(pend_account) and must return to the baseline; the Some(false) startup message also names a refused option. Both
confirmed the won exit (fd in t.conn on both callers, closed once by close_target) and the lowat field reads.

## Release-note lines
- New: `--download-rate RATE` (per connection) and `--upload-rate-per-stream RATE` (per TCP stream) cap bandwidth with
  kernel TCP pacing (bytes/s, K/M/G; off by default). A download cap turns splice off and lowers the client lowat.
