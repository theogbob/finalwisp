Design: 60.28 C5 (a research branch (not published): the prototype `metrics::serve` / `prom`, its review fold-ins), decision
d (127.0.0.1 by default, no auth). Code: `server/src/prom.rs` (page, request check, the `metrics-http` thread),
`server/src/metrics.rs` (`sum`: the one merge rule for the line and the page; `Stats::help` from the counter doc
comments), `cli.rs` (`--metrics-listen`), `main.rs` (bind before the workers, the thread after the startup lines).
Operations: 40.01 "Metrics"; flag: 40.03; compat: `tests/compat/prom.py` (wispsuite step `prom`, ports B+68, B+69).

## Decisions as built
1. `--metrics-listen [ADDR:]PORT`: PORT, IPv4:PORT or [IPv6]:PORT; a bare PORT = 127.0.0.1 (decision d). A `--config`
   key like every flag (`metrics-listen 127.0.0.1:9464`). Refused (exit 2): the Wisp port (by number, whatever the two
   addresses: one port, one service; `cli::check` on the final command line, not per config line: review), port 0, a
   name instead of an IP. Bound in main before the
   memory budget and the workers start; a bind failure exits 2 (`--metrics-listen ADDR: cannot listen: ...`), so no
   Wisp listener ever opens. A non-loopback address prints a warning (warn level); `metrics on http://ADDR/metrics`
   at info. Off: no socket, no thread, nothing else changes (Stats layout untouched).
2. Thread `metrics-http`, std blocking `TcpListener`, serial accept loop (an accept error sleeps 10 ms: EMFILE).
   Per connection a 2 s total deadline: read and write timeouts are set from the time left before every call, so a
   client that drips bytes cannot extend it (compat: closed at 2.07 s; a stuck client delays the next scrape 1.9 s).
   The head is read to the blank line (CRLF CRLF, or LF LF) before answering, at most 8 KiB (more = 400); after every
   answer the thread half-closes and reads the leftovers (a body, a pipelined request, the rest of a big head; <= 64 KiB,
   within the deadline) so that the close does not RST the answer away (review: first only after a 400). EINTR is retried. EOF / timeout / error before a full head: closed without an answer.
3. Hand parser of the request line only (no httparse: 60.28, a second caller changed handle_http's inlining):
   `METHOD SP /target SP HTTP/1.0|HTTP/1.1`, exactly three fields, uppercase method. GET /metrics (any query) 200; another path
   404; another method 405 (Allow: GET); anything else 400. `Connection: close` always; 200 has
   `Content-Type: text/plain; version=0.0.4; charset=utf-8` and Content-Length.
4. Page (`prom::render`): the metrics line's values. Named counters through `metrics::sum` (the code line() uses:
   sums, `_max` by max), counters `finalwisp_<name>_total`, gauges by an explicit list (`GAUGES`: pool_chunks,
   pool_dirty_kib, streams and the three `_max`; a unit test fails if a `_max` counter is missing from it), HELP =
   the counter's doc comment (`Stats::help`, joined lines; escaped `\\` and `\n`), TYPE for every family.
   `finalwisp_close_total{reason="0x49"}` for reasons sent at least once. Base-unit renames (`RENAMES`):
   pool_dirty_kib -> pool_dirty_bytes (x1024), ktls_starve_ms_max -> ktls_starve_max_seconds (/1000),
   ktls_starve_read -> ktls_starve_read_bytes_total, ktls_starve_conn_max -> ktls_starve_conn_max_bytes. Process-wide:
   build_info{version}, uptime_seconds, connections, conns_reserved / conns_max (with --max-conns), memory_level,
   memory_used_bytes (with a budget), memory_level_changes_total, memory_level_seconds_total{level}, the tcp_* values
   (with --tcpmem-adapt; tcp_own_ratio 0-1 instead of per mille), host_tcp_pressures_total /
   host_tcp_pressure_seconds_total, keyupdate_closes_total, pool_release_(cpu_)max_seconds, process_resident_bytes,
   metrics_scrapes_total. No per-client / per-destination label, no secret, address or name (conns_max is --max-conns).
   HELP of a renamed counter is rewritten in the new unit; the doc comments were reworded so they read as HELP text
   (review; the "new counters go last" rule is a plain comment now).
5. `metrics_scrapes_total` is a static in prom.rs (one writer: the thread), not a Stats field: no counter was
   added to Stats, so its layout and the workers' code are unchanged.

## Fixes after the merge (branch c5-fix; reviewer B post-fix review, )
1. [P2] The time counters (`memory_level_seconds_total{level}`, `memory_level_changes_total`,
   `tcp_level1_seconds_total`, `tcp_level_enters_total`) could go back without a restart: the sampler stored LEVEL,
   woke the workers, then accounted the old episode (note_level), and a read in between credited the whole old episode
   to the new level and lost it at the next read (TCP: the same with TCP_LEVEL and TCP_L1_*). Now a seqlock in mem.rs
   (`times_write` in the sampler around the level store and its accounting, `times_read` in level_times / tcp_times):
   one writer, readers retry while a write (a few stores) is in progress. The metrics line gets the same coherent read.
   Second review round (reviewer B): a reader whose clock ran ahead of the sampler's could count an open episode past the
   time the sampler then closed it at; readers now publish the time they count up to (`TIMES_READ_MAX`, fetch_max)
   and the writer closes / opens at no earlier time (a SeqCst fence on both sides: either the writer sees the
   reader's time or the reader sees the odd sequence and retries). Unit tests `times_read_sees_whole_writes` and
   `times_write_starts_at_or_after_a_read` (a mutation of each fails its test). Chosen over gauges:
   these are counters (rate() over them is the use).
2. [P2] compat `prom.py` req() swallowed receive errors, so the "no RST" checks passed on a reset or a truncated
   answer. Now strict: a reset, a timeout, no clean EOF or a body that is not Content-Length bytes fails the check.
3. [P3] `metrics_scrapes_total` counts 200 answers written in full (it counted requests before the write); a page
   shows the scrapes before it.
