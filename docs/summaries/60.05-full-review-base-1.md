## Decisions (D1 decided by the maintainer 2026-10-24)
- D1 DECIDED: the binary has no limits when run with no config. The repo ships a default config file (C8 flags file) with
  high, semi-protective limits (C3 flags), set high enough not to touch benchmark scores. So C3 + C8 come early in Phase C.
- D2 open. Fact checked: wisp-js connection.mjs send() puts whatever the app passes to send() into ONE DATA packet = one WS
  frame, unsplit. So "real clients send <= 64 KiB" is not guaranteed; a cap below 16 MiB can break a real app. Proposal:
  binary keeps 16 MiB; C3 adds --max-frame; the shipped config may lower it after testing real clients.

## Original decision notes
- D1 file descriptors: the memory budget counts bytes, not fds. One connection can open ~16k CONNECTs to a blackholed IP
  (4 fds each for 10 s) and exhaust RLIMIT_NOFILE for everyone. Options: (a) a high built-in safety cap (streams per
  connection, e.g. 4096, plus total fds below nofile) now; (b) keep "no limits by default" and ship C3 first.
- D2 client frame size: H2 removes the amplification. A cap (e.g. 1 MiB, close 1009) is extra safety but could break a
  client that sends bigger frames; real clients send <= 64 KiB. Default: no cap, H2 only.

## Perf levers left inside the principles (measure after hardening; none is large)
- splice gate (worker.rs:2454): allow splice when no splice is pending and the bulk lane is empty, not only when both
  lanes are empty. flush() already supports obuf-before-marker. Medium risk (output order); expected gain on download
  10x10 and the page test, size unknown.
- connect_state: skip poll() when epoll reported OUT without ERR/HUP (one syscall per stream on churn/rr).
- set TCP_NODELAY / TCP_NOTSENT_LOWAT on the listener so accepted sockets inherit them (2 syscalls per accept; inheritance
  to be verified on 6.8 and 7.0).
- UDP: recvmmsg straight into obuf; sendmmsg for upload bursts.
Already rejected, do not reopen without a new profile: MSG_ZEROCOPY, framing/CONTINUE cadence, allocator swap, unmask fusion,
vmsplice header, TCP_CORK on kTLS, io_uring as default (opt-in only; est. 5-15% rr/churn, nothing on bulk).

## Limits (would need to break the platform-neutral rule)
Bulk is near the floor: zero-copy download, upload = read + in-place unmask + writev, kTLS cipher is the TLS ceiling.
What is left needs pinning + SO_ATTACH_REUSEPORT_CBPF (5-15% rr/churn on bare metal, nothing on VPS/loopback), busy
polling (latency at 100% CPU), or operator choices (init_on_alloc=0: 12-15% of bulk samples are page zeroing; bigger
tcp_wmem for one fat stream; NIC kTLS offload). Huge pages, AVX-512/SVE, AF_XDP: no gain. The real ceiling is
architectural and deliberate: one WebSocket = one core (shared-nothing).
