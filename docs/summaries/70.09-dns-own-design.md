# 70.09 Own DNS resolver (C9, `--dns-own`): design

Pointers: 60.02 C9, net.rs DNS pool (20.19 coalescing, 20.23 negative cache contract), worker.rs new_target/resolve/inbox_ready,
70.01 (fuzzing). Status: IMPLEMENTED (design approved; see "Implementation" at the end). Branch dns-own (from b12-harden 2731789).

## Why
musl's getaddrinfo is not usable for us (no AAAA+A in one call before 1.2.4, no search/ndots quirks match, static builds),
and glibc waits timeout x attempts (5 s x 2 = 10 s) for a dead nameserver while a pool thread is blocked.

## Shape (boring: reuse the pool)
- New `server/src/dns.rs` (~550 lines + tests): wire format, resolv.conf/hosts parsers, `lookup(name, deadline, cancel)`.
- `net::start_dns_pool` keeps threads, coalescing, inbox delivery and `DnsResp {addrs, nx}`. With `--dns-own` each pool thread
  calls `dns::lookup` instead of `net::lookup`. No other caller changes. getaddrinfo stays the default.
- `DnsReq` gains `at: Instant` (admission). Off: one Instant::now() per DNS request (not per packet), nothing else.

## Lookup algorithm (one pool thread, blocking poll() on its own sockets, no extra threads)
1. Reject: len > 253 (after trailing dot), empty or > 63-byte label, NUL -> Err(false) (not cached, as now).
2. /etc/hosts first (name match case-insensitive, all addresses of every matching line, v4+v6). Hit -> Ok.
3. Candidates from resolv.conf: trailing dot = absolute only; dots >= ndots -> as-is, then each `search` suffix; else the
   reverse (glibc order). `domain` = one-entry search list. Search list capped at 6 entries. **Superseded (60.18 #16,
   branch dns-abs):** client names are asked as absolute names only; search / domain / ndots are not parsed any more.
4. Per candidate: A and AAAA queries sent at once (two connected UDP sockets, kernel-random source ports, random 16-bit IDs
   from getrandom; EDNS0 OPT with 1232-byte payload, no DO bit). poll() both. Per family: done on NOERROR (addresses or
   NODATA) or NXDOMAIN; SERVFAIL/REFUSED/NOTIMP/timeout -> that family moves to the next server (rotate if `options rotate`);
   FORMERR with EDNS -> resend once without OPT; TC=1 -> same query over TCP to the same server (2-byte length prefix, same
   deadline). A family that fails does not drop the other: an A failure + AAAA addresses = Ok(AAAA).
5. Accept a reply only if: from the connected server (kernel filters), ID matches, QR=1, opcode 0, question echoes our
   name (case-insensitive) / type / class IN. Answers: follow the CNAME chain from qname (max 8 hops), take A/AAAA whose owner
   is the chain end; compression pointers must point backwards, max 32 jumps, names <= 255. Anything malformed = ignore the
   packet (keep waiting; a spoofed garbage packet cannot fail the lookup).
6. Result: addresses from the first candidate that has any -> Ok (order below). All candidates definitively negative
   (NXDOMAIN or NODATA for both families) -> Err(true) (cached 5 s as now). Anything else -> Err(false) (never cached).
   Note this is stricter than glibc's EAI_NONAME (we know NODATA vs SERVFAIL per family; 20.23 review concern goes away).
7. Order: AAAA first only if the host can route to the first AAAA (one connect() of a UDP socket, glibc RFC 6724 rule 1
   equivalent), else A first. worker.rs then interleaves + he_prefer exactly as today. Filtering (loopback/private) stays in
   start_connect: the resolver returns unfiltered addresses, same as getaddrinfo now.

## Deadlines and cancellation
- T = per-server window = min(resolv.conf `timeout`, 2 s), at least 1 s (default resolv.conf timeout 5 -> 2 s).
  tries = min(servers x attempts, 3). Deadline = admission + T x tries (worst 6 s; dead single server, attempts 2: 4 s, glibc
  10 s). Time spent queued counts: a request dequeued past its deadline answers Err(false) at once.
- Cancel: `Inbox` gains `cancel: Mutex<HashSet<u64>>`. close_target of a Resolving target inserts its token (only with
  --dns-own: one branch on that path). A pool thread checks its waiters' tokens before starting and whenever poll() returns;
  the lookup stops when every waiter (coalesced) is cancelled. Every request still gets exactly one DnsResp (Err(false)), and
  inbox_ready removes the token: the set cannot grow past in-flight requests. Granularity: a reply or one window T.
- Config reload: resolv.conf and hosts are re-read when their mtime changed, checked at most once per second (glibc >= 2.26
  does the same for resolv.conf). Missing/empty resolv.conf: nameserver 127.0.0.1 (glibc default), warning at startup.

## Flags
- `--dns-own` (off). Proposed also: `--dns-server IP[:PORT]` (repeatable; replaces resolv.conf nameservers; implies
  --dns-own). It is the "custom DNS servers" half of C9 and the only way to test on unprivileged ports (bwrap cannot bind 53
  here). Alternative if you prefer no new user flag: a hidden test-only env var. -> your call (Q1).

## Not in scope
DNSSEC, DoT/DoH, TTL-driven caching (worker cache keeps its fixed 30 s / 5 s), `options inet6/single-request`, nsswitch.conf,
mDNS/.local, IDN (names are passed through as bytes; non-LDH accepted as glibc does).

## Tests
Unit: query encode, response parse (CNAME chain, compression loops, truncation, wrong ID/question), resolv.conf/hosts parsing,
candidate order. Fuzz target `dns-parse` (response parser vs a fixed query; never panics; accepted addresses only of the asked
family) + regress corpus. Functional: tests/compat/dns_own.py = Python fake DNS (UDP+TCP) on 127.0.0.1:PORT with names for
NOERROR, NXDOMAIN, SERVFAIL, timeout, TC->TCP, A-SERVFAIL+AAAA-ok, CNAME, FORMERR-on-EDNS, garbage-then-good, second-server
fallback; through a real finalwisp + Wisp CONNECT (CLOSE reason 0x42 vs data). dnsmasq run too if `--dns-server` exists.

## Questions
Q1 `--dns-server IP[:PORT]` as a real flag (recommended) or hidden test hook? Q2 deadline numbers (T 1-2 s, max 3 tries,
worst 6 s) OK? Q3 cancellation granularity "one window" (no per-thread wake eventfd) OK?
Confidence: medium-high (design); the security-sensitive part is reply validation (5), covered by fuzz + tests.

## Implementation (branch dns-own)
Approved answers: Q1 public `--dns-server IP[:PORT]` (repeatable, at most 3, implies --dns-own), Q2 numbers as above,
Q3 no wake fd. Lead additions done: hosts/resolv.conf re-read on mtime/inode/size change (at most 1/s), IPv6
nameservers incl. `fe80::1%iface`, the 127.0.0.53 stub works (laptop: example.com/google/cloudflare via
systemd-resolved, NXDOMAIN 0x42), ephemeral port + random ID per query, replies from other addresses never reach us
(connected sockets; tested with a spoof from another port).
- dns.rs ~520 lines + ~370 lines of tests. Cancel = `Inbox.dns_live` token set (worker inserts before the send, removes
  on the answer or in close_target of a target waiting for the pool); the pool checks it after every poll() wakeup and
  before each candidate. Every request and coalesced waiter still gets exactly one DnsResp (dns_inflight stays exact).
- Changes after review (three reviewers; reviewer A + reviewer B, reviewer C had no credits): a failed UDP send no longer reused the old
  server's socket for the next server; at most 16 datagrams per wakeup; FORMERR resend inside its window; EDNS
  extended RCODE, referrals (NS without SOA) and CNAME loops / chains over 8 hops are failures (not cacheable NODATA).
  Kept deliberately: the TCP retry after TC gets a fresh window (bounded by the shared deadline).
- Tests: 9 unit tests (wire, validation, compression, CNAME, sections, config, candidates, fake-server lookups,
  reload) + a pool cancel test; fuzz target `dns-parse` (2 runs, 8.0 M execs, 0 crashes; regress/dns-parse);
  tests/compat/dns_own.py (compat step `dns-own`, 17 checks); `--dns-own` is in the compat --matrix.
- dnsmasq 127.0.0.1:5399 (`--dns-server`, upstream 127.0.0.53): local `--address` name, a forwarded name and
  NXDOMAIN are correct. A local v4-only name waits for the deadline (4 s): dnsmasq does not answer its AAAA query at
  all (dig times out too).
- Was KNOWN BEHAVIOUR in 70.09 (a family never answered held the connect until the deadline, 4 s): fixed by 70.10 below.

## 70.10 RFC 8305 resolution delay with late updates (IMPLEMENTED, branch ops 2026-10-27; original plan below)
After the first family has addresses (+ up to 50 ms), deliver them so the connect starts; keep the other query to the
normal deadline and deliver a late update for the same token; the worker appends it to the happy-eyeballs list of a
target still connecting, and a target whose early addresses all failed waits for it before CLOSE. Touch points:
DnsResp `more` flag (two responses per token; dns_inflight / dns_live / cache only on the final one), a Target flag,
try_connect + the run_timers connect scan park instead of fail, late append (filter, dedupe, order), close_target
cancel, pool early delivery incl. coalesced joiners. Tests: AAAA never answered -> ~50 ms; unreachable A + AAAA at
300 ms -> connects via AAAA; both late/failed -> CLOSE at the deadline. Estimate 2-3 h.

### 70.10 implementation (branch ops)
- dns.rs ask(): when one family has addresses and the other is still asked, its addresses go out once through the
  lookup's `early` callback: A after RESOLUTION_DELAY = 50 ms (RFC 8305 s3), a routable AAAA at once (a non-routable
  AAAA waits the 50 ms like A). The other query runs on to the normal deadline; the final Ok holds both families
  (same order rule as before). One early answer per lookup (the candidate that has addresses ends the search).
- net.rs pool: DnsResp.more = early. Sent to the request and every coalesced waiter under the InFlight lock; the entry
  keeps the early set, so a request joining later gets it on joining: each waiter sees at most one early answer and it
  always precedes its final one. The final response is unchanged: exactly one per request; only it counts for
  dns_inflight, the dns_live token and the cache (full set cached). getaddrinfo (default) never answers early.
- worker.rs (scope approved by the lead): Target.dns_more (fits the padding: size_of::<Target>() 232 -> 232).
  inbox_ready: early -> a Resolving target with no addresses connects on them (start_connect, he_prefer as usual).
  While dns_more, "no address left and nothing in flight" parks the target (unlisted, no attempt) instead of failing:
  try_connect, the connect deadline in run_timers (err = ETIMEDOUT), udp_open (all early addresses failed),
  start_connect (every early address filtered: stays Resolving). The final answer -> dns_late: Open = nothing;
  Resolving with no addresses = start on the full answer; else net::he_append puts the new (filtered, deduplicated)
  addresses into the untried tail, starting with the family the last attempt did not use, interleaved; a parked target
  tries the next one at once or fails with the last connect error (0x43 after a timeout, 0x44 refused, 0x42 none).
  close_target cancels the lookup (dns_live) also while dns_more. Hot path untouched.
- Tests: dns early_family_delivery (v4only / aaaaonly / AAAA 300 ms late / both at once), net
  own_dns_early_answer_reaches_every_waiter_once (early to the first waiter and to a later joiner, one final each) and
  dns_coalescing_answers_every_waiter (default path: no `more`, nothing after the final), he_append order, worker
  early_dns_answer_and_late_family (late AAAA while connecting: no second connect; early refused: parked, then via ::1;
  closed while due: dns_inflight/dns_live back to 0; deadline while parked: CLOSE 0x43); mutation: without the park the
  worker test fails. tests/compat/dns_own.py: v4only 52 ms (was 4.0 s), v6only 41 ms, AAAA 300 ms late = one v4
  connection, A refused + AAAA late = via ::1 at 301 ms, early connect timeout while AAAA never answered = 0x43 at the
  lookup deadline (local blackhole: a backlog-0 listener with a full accept queue). Fuzz: the worker harness runs with
  dns_own and names containing "late" get an early answer, the final one a turn later; quiescence also checks dns_live;
  seeds v1-late / late (regress copies).
- Review (three reviewers; reviewer A + reviewer B, reviewer C 402): reviewer A P1 UDP early addresses all failing closed with 0x42 -> fixed
  (udp_open parks while dns_more); reviewer A P3 fuzz dns_live check -> added; reviewer B: dns_own.py deadline bound now derived
  from /etc/resolv.conf (window x tries) instead of a fixed 3 s.
