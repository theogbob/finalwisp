# 70.12 Static glibc build (crt-static) check (2026-10-25)

Pointers: 70.09 (--dns-own, branch dns-own), 70.03 (mallopt pin), 30.10 (gates). Base: b12-fix 0be0ff1; branch
static-glibc. Data: raw data (not published).

## Build
`RUSTFLAGS="-C target-feature=+crt-static" cargo build --release --target x86_64-unknown-linux-gnu` (the explicit
--target keeps build scripts and proc macros dynamic). Result: "ELF 64-bit LSB pie executable ... static-pie linked",
ldd "statically linked", no PT_INTERP. 11.5 MB (dynamic 10.3 MB). No new build config needed.
Link warning (rustc's default lld hides it; relinked with ld.bfd): `warning: Using 'getaddrinfo' in statically linked
applications requires at runtime the shared libraries from the glibc version used for linking`. dlopen and the NSS
loader (__nss_module_load) are in the binary; files and dns are built in (glibc >= 2.34).

## DNS (Wisp CONNECT to a hosts-file name -> local echo, and example.com:80)
| where | nsswitch.conf hosts | static, getaddrinfo | static + fix (below) | dynamic |
|---|---|---|---|---|
| bwrap empty root (/etc = hosts + resolv.conf only) | none / files dns / files mymachines resolve dns / Ubuntu default / laptop (mdns4_minimal) | ok | ok | (needs the host libs) |
| laptop root, glibc 2.43 (= link version) | laptop default; mymachines resolve | ok (strace: dlopens libnss_mdns4_minimal, libnss_mymachines and **libc.so.6**) | ok, no NSS dlopen | ok |
| docker debian:12 (glibc 2.36) | image default, `files hesiod dns`, `files compat dns`, absent modules | ok | ok | |
| docker alpine (no glibc) | same | ok | ok | |
| docker ubuntu:24.04 (glibc 2.39) | image default, absent modules | ok | ok | |
| docker ubuntu:24.04 | `files hesiod dns`, `files compat dns` | **server dies: SIGFPE (exit 136) at the first lookup** | ok | |
Cause: when nsswitch.conf names a module that exists on the host, glibc dlopens it, and that loads the host's
libc.so.6 and ld.so into the static process (seen in /proc/1/maps on debian:12: libnss_compat.so.2, libc.so.6,
ld-linux-x86-64.so.2). glibc does not support this mix. The result depends on the version: debian:12 (2.36) survived
the lookup, ubuntu:24.04 (2.39) died with SIGFPE, and the laptop (2.43, the same as linked) worked. Modules that are
absent are skipped (ENOENT) and the lookup falls through to files/dns. Nothing hung.
**Fix (main.rs nss_builtin_only, crt-static builds only):** `__nss_configure_lookup("hosts", "files dns")` before
any thread: hosts lookups use only the built-in modules, nsswitch.conf is ignored for hosts (capability line:
`static: hosts via files dns (nsswitch.conf ignored)`). Side effects (glibc nss_database.c): nsswitch.conf is not
reloaded for the life of the process (all databases; this server only uses hosts: getaddrinfo with a NULL service and
no AI_IDN, no passwd/group/services lookups), and nscd is bypassed for hosts.
Cost: names that only an NSS module knows do not resolve: avahi mdns4_minimal without systemd-resolved, mymachines,
LDAP/NIS/sss, and myhostname when resolv.conf is not the resolved stub. With the stub (127.0.0.53, the Ubuntu default),
resolved's own names (local hostname, _gateway, its mDNS/LLMNR) still resolve through dns. musl and --dns-own behave
the same way.
Requirement: the build host's glibc must be >= 2.34, the version where files and dns became built in (here 2.43).
Linked against an older glibc, files and dns are themselves dlopened, and this fix does not help.
No other dlopen path is reached (review): IDN needs AI_IDN (not set); gconv needs iconv or a locale (not used);
unwinding uses the static gcc_eh, and panic = abort.
--dns-own (branch dns-own 91d2024, static build without the fix): reads /etc/hosts + resolv.conf itself, ok in
every case incl. ubuntu:24.04 `files compat dns`; without --dns-own the same binary crashes there.

## Idle memory (wst idle, --threads 2, 2000 conns, 6 reps)
dynamic 4.6 KiB/conn, static 4.7 (p 0.84, tie). Both builds have the same occasional slow-settle outliers (48-151 KiB) at the 3 s settle.

## Review (three reviewers: reviewer A, reviewer B; reviewer C out of credits)
No code defect. Doc changes applied: the crash is version-dependent (debian:12 2.36 loaded the foreign libc.so.6 and
survived), side effects of __nss_configure_lookup, the cost is narrower with the resolved stub, the glibc >= 2.34
build requirement, and cargo test does not cover main.
