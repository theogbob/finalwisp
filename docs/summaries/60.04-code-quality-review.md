## Verdict: READY WITH FIXES

base-1 is a good base for Phase C on the code-quality axis. The code is coherent, the comments explain the
measured reasons behind the numbers, the dependency set is tiny, there are no compiler warnings, the default Clippy
run gives 9 style warnings, and every network-facing parser is bounds-checked. The Phase C hooks that 60.02 names
(accept, upgrade, CONNECT, connect completion, close, idle sweep) all exist as clear control points, so C1-C4 and C6-C9 can
be added without edits to `read_target`/`flush`/`splice_target`/`flush_upload`. 60.02 itself plans two data-path
edits: C5 (`rx_bytes` per client read) and C10 (splice length, read pause).

Gates before Phase C work starts (about 1 day in total; all off the data path, or one branch on it):
- **F1** a stale `dirty` index can abort the whole process under memory pressure (P1, S; confirmed by all 3
  reviewers), with a targeted regression test;
- **N1** runtime `eprintln!` (mem.rs:491, main.rs:49-50) panics if stderr fails (e.g. a dead log pipe), and under
  panic=abort that ends the process; a blocked stderr also stalls the memory sampler (P2, S);
- **N2** `bench/gates.py` always exits 0, and its cargo step reports grep's status (P2, S);
- **F2** pin the compiler that built base-1 before any OFF-vs-base-1 A/B (P2, S);
- the written rules **F5** and **F6b** for Phase C authors.
Gates tied to one feature: **F3** (one admission function for Wisp CONNECT and wsproxy) with or before C1/C3;
**F4** (CLI parser out of `main()`, with tests) before C8. The `--connect-timeout` range check in F4 is S and can go
in with F1. Everything else is nice to have.

Review: one `review(three reviewers)` round on this draft (reviewer A, reviewer B, reviewer C, ).

## 1. Structure
- Modules: main (CLI, startup line), worker (event loop, 3448 lines), net (socket/DNS helpers), tls (rustls + kTLS),
  mem (budget, sampler, counting allocator), ws, http, ext. The boundaries are clean: only worker.rs holds
  connection state; the other modules are stateless helpers or startup code.
- worker.rs is big but ordered in sections (client input, TLS, HTTP, streams, pressure, timers, download, upload,
  close, UDP, output). Splitting it is not needed for Phase C. If it is ever done, do it as pure moves of `impl Worker`
  blocks into `worker/*.rs` and only before the C branches fork (nice to have, not recommended now).
- Phase C fit (60.02 §0): every hook point named there exists and is off the data path. Recommended layout: the
  feature logic goes into new modules (`policy.rs` C1, `realip` in http.rs C2, `limits.rs` C3, `log.rs` C4,
  `metrics.rs` C5, `upstream.rs` C6, `config.rs` C8); worker.rs only gets the call sites.
- Things Phase C designers must know:
  - The admission checks are duplicated (F3).
  - The epoll token has 2 kind bits, and all 4 kinds are used (worker.rs:97-100). C7 (unix listener) must use
    `K_LISTEN` with a different idx; it cannot get a new kind.
  - `dispatch` sends every `K_LISTEN` event to `accept_all` on `self.lfd` without looking at idx (worker.rs:860), and
    `accept_all` sets TCP-only options without a check (910-913). C7 must first tell the two listeners apart, then
    branch on the options.
  - C3 `--max-conns`: 60.02 sums `Inbox.load`, but each worker increments its own counter (930-935). Check and
    reserve must be one atomic step across workers, with rollback when `adopt` fails (946-947, 1018-1020). The
    `--balance` handoff `adopt`s (1763) without the `st.admit` check, so a per-worker C3 check placed only in
    `accept_all` would be bypassed there.
  - C6 is the only feature that changes the target state machine: a proxy-handshake state between Connecting and
    Open; `won`/`connected`/`target_event` must not deliver to the client or flush `pend` before the reply; TFO off
    with an upstream. `run_timers` skips every state except Connecting (2331-2332), and 1858 resets the deadline per
    attempt. So a Proxy target that stays on `connecting` (as 60.02 plans) gets no timeout until that check changes,
    and an overall deadline needs its own field. It is the highest regression risk in Phase C and needs its own
    adversarial tests.
  - 60.02 rule 3 (side vectors parallel to the Slab) brings back the bare-index hazard of F1/F5.

## 2. unsafe + libc
Audited every unsafe block. **No unsound block found.** Details:
- fd lifecycle: all fds are created with CLOEXEC; every error path after `socket`/`accept4`/`pipe2` closes the fd
  (net.rs:108-121, 157-187, 271-284; worker.rs:946, 1018, 1843, 2547, 3037). Targets close `fd` and every HE attempt
  (close_target 2937-2941; won 1918; run_timers 2335). Clients are closed once (`dead` guard, close_client 2999) and
  their slot is freed only at the end of the loop turn (806), so the `rbuf` pointers stay valid during the turn.
  Only leak: `Worker::new` leaks `lfd`/`ep` on its error path (693-703); the process exits right after (F9).
- EINTR/EAGAIN: `would_block` covers EAGAIN/EWOULDBLOCK everywhere; only `epoll_wait` retries EINTR (770). On these
  non-blocking fds EINTR cannot happen today, because the process installs no signal handlers (SIGPIPE ignored,
  SIGHUP blocked + sigwait). This becomes a rule for Phase C (F7).
- Slices and lengths: `ws::parse`, `http::parse`, `ext::parse_records`, `on_message`/`on_connect` body parsing,
  `tls::record_len` (caller checks 5 bytes, 1410), `client_hello`, UDP pend records, `recvmmsg` lengths: all
  checked. The download header write (worker.rs:2478-2498) is in bounds: `reserve(room + CHUNK)`, `n <= CHUNK`, and
  every byte up to `set_len` is written (checked for all 4 cases: wisp/raw x 2/4-byte header). That proof depends on
  `CHUNK + ROOM_WISP - 4 <= 65535`; a `const` assert should hold it (F6).
- Aliasing: `process_frames` (1172) extends the frame slice's lifetime across `&mut self`. The SAFETY comment is
  correct today: nothing in `on_frame` resizes or frees `rbuf` (`close_client` keeps it; only `idle_sweep`,
  `set_level`, `read_client` and the dead drain touch it, and none of them runs inside `on_frame`). `rbuf` is a
  separate heap block, so `&mut Client` reborrows do not cover it. This rule constrains Phase C: no hook reachable
  from `on_frame` (C1/C3 in `on_connect`, C4 logging, C10 limiter) may free, shrink or reallocate `rbuf`, or
  overwrite payload bytes that staged iovecs still point to (staged at 1313, sent at 2671/2699, last flush at
  1130) (F6b).
- Casts: no cast on a value from network input truncates. Operator input: `--connect-timeout` near u64::MAX panics
  at `Instant + Duration` on the first connect (worker.rs:1858) (F4). (`--notsent-lowat` > i32::MAX is harmless:
  the cast keeps the bits, and the kernel stores the value as `u32 notsent_lowat`. A draft claim that it fails was
  wrong.)
- FFI style: libc constants not exported are hard-coded with their header names (SO_BUF_LOCK 72, SIOCOUTQNSD,
  SIOCATMARK, TCP_ULP/SOL_TLS); the kTLS crypto_info structs have a const size assert (tls.rs:63). Fine.
- Documentation: 3 of 100 blocks have SAFETY comments. Most blocks are a libc call with pointers to locals, so
  nothing is missing there. About 10 non-trivial ones should get a comment (F6).

## 3. Error handling and panics
- `Cargo.toml` sets `panic = "abort"`: any panic in any thread ends the whole process (all workers and connections).
  That is a valid choice (it is simple, and systemd restarts the process), but it is not written down (F15). History:
  the 20.09 review found a re-entry panic that killed the process (20.06).
- Network-reachable panics: none found in parsers. The remaining panic class is a logic error with bare slot
  indices: `Slab::at` unwraps (worker.rs:149-151, about 150 call sites). F1 is one concrete instance.
- Runtime logging: `eprintln!` panics when the write to stderr fails (std docs). EBADF (fd 2 closed) is ignored by
  std, but EPIPE (a log pipe whose reader died; SIGPIPE is ignored) is an error, and so it panics. The runtime call
  sites are mem.rs:491 (memory level change, in the sampler thread) and main.rs:49-50 (SIGHUP reload). Workers do
  not log. A stderr that blocks also stops the sampler before it publishes the new level (N1).
- `unwrap`/`expect` outside tests (18): fixed-size `try_into` (infallible), `parse` after `is_ok`, mutex `lock()`
  (cannot be poisoned under panic=abort), thread spawn at startup. `panic!` at worker.rs:773 only for a failing
  `epoll_wait` that is not EINTR.
- Errors are propagated as `Result<_, ()>` / CLOSE reasons inside the worker. Startup errors print a message and
  exit, and they say what to do (for example the kTLS module hint). Silent `let _ =` / ignored setsockopt results
  are best-effort by design (lowat, caps, nodelay).
