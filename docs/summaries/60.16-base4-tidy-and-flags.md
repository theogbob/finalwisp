## 3. Flag inventory and recommendations (after the design review)
Design review (review three reviewers, no diff; reviewer A, reviewer B, reviewer C, ), on my first draft:
- **HIDE rejected by all 3.** A hidden flag is still parsed, fuzzed, run in `--matrix` and unit-tested, so the surface
  is the same as KEEP; HIDE only takes the flag away from the operator. Rule adopted: **in usage, or deleted**. Off-switches
  move to an "advanced / diagnostic" section of USAGE and of 40.01.
- **`--no-tfo` KEEP (all 3):** my reason "the admin has net.ipv4.tcp_fastopen" breaks "no required sysctls". The sysctl is
  host-wide and often not writable in a container, and a middlebox that drops SYN+data does not trigger the
  EOPNOTSUPP latch (net.rs:253-283).
- **`--notsent-lowat` KEEP-ADVANCED (all 3):** 0 = leave kernel policy is a real off-switch. 20.19 s2.3 measured +5% of a core
  at ~950 Mbit, and kTLS needed the 20.21 adaptive lift. Not measured above 1 Gbit.
- **`--no-keepalive` KEEP-ADVANCED:** net.rs:238-241 tells the operator to pass it when listener keepalive setup fails
  (reviewer C, reviewer B). It also covers TCP targets (70.13).
- **`--no-splice` KEEP-ADVANCED:** reviewer A notes bench/browser/REPORT-busy-2026-10-24 found `--no-splice` better in 25/32
  busy browser page loads (256 KiB splice frames; the splice64 follow-up is not on master). Note: that is browser-sim evidence
  from one report, not a 60.12 suite verdict.
- **`--tcpmem-adapt` evidence was stale in my draft (all 3):** I cited the pre-redesign 60.14 cost. On master is the
  **B redesign** (20.31:426-498): pressure cells no longer lose (download 1.01-1.11, burstidle 0.98-1.05, CPU per MiB ~1.0x
  vs 2.4-2.8x), echo keeps 1.5-1.8x with ~4x lower peak, 0 reproduced LOSS on VPS1/VPS2. Still open: n.s. watch cells,
  1 Gbit only on VPS1, no quiet-laptop A/B, and the 60.12 side-rr rescore. Off cost at runtime is about 0 (gated at startup).
  The code is about 300+ lines (mem.rs 1228-end, main.rs 333-502, worker.rs tcp_only_local + tests).
  **reviewer A and reviewer B: REMOVE** (few knobs; needs cgroup v2, host netns, 5.15+ and credit v2). **reviewer C: KEEP documented
  opt-in** (the only sysctl-free remedy for small-VPS tcp_mem collapse, 20.31:35). Never HIDE. **User call.**
- **`--no-credit-v2` KEEP permanently (reviewer B, reviewer C):** not "HIDE later". A client that never pongs already falls back to the
  base-2 rule (PONG_LATE, credit.rs:35/111), so the flag is a general rollback for a protocol-visible change (pings after
  CONTINUE; 2.5-4.4% single-stream upload cost, 60.13/60.14).
- **`--no-dns-coalesce` REMOVE (all 3):** delete the 4 `if coalesce` branches in net.rs:749-814 too (otherwise it saves
  nothing). Keep the negative-over-positive cache guard (worker.rs:2237).
- **No-op aliases REMOVE (all 3), with a migration note:** they are not pure no-ops, because parsing is last-wins
  (`--tcpmem-adapt --no-tcpmem-adapt` = off; cli.rs:220). A base-3 unit file that carries one would exit 2
  ("unknown argument") on base-4. Say so in the base-4 release notes. Callers to update: tests/compat/credit_v2.py:155,
  bench/wispsuite/compat.py:212, fuzz cli_parse.rs:25/27, cli.rs tests.
