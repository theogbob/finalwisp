## RC2 fixes (since RC1)
- C6 socks5h: `.onion` names (RFC 7686, any case) go to the proxy without the added trailing dot. In RC1 every onion
  service through Tor failed with 0x42 (Tor refuses `x.onion.` with SOCKS REP 04). Other names keep the absolute form
  (60.32 #9). Found by the real-Tor check (40.01 "Tor upstream"; onion-fix).

## Default changes (behaviour without any new flag)
- **One: `rx_bytes`** (60.25 Q6: always on, no flag). Each client read adds its byte count to a worker counter; the
  metrics line and /metrics show the sum (`rx_bytes`, `finalwisp_rx_bytes_total`). No other behaviour changes. A/B:
  tie (60.25, Q6 layout control on VPS1, 128 pairs; see "A/B" below).
- None in behaviour for every other feature. Checked in each as-built note:
  - C4 step 1 (60.24 decision 1): with the defaults, stderr is byte for byte base-5 (timing numbers masked).
  - C5 (60.29): off = no socket, no thread.
  - C10a (60.30): both caps 0 = off; no setsockopt; splice and lowat unchanged.
  - C10b (60.25): off = no limiter: the read path is unchanged apart from the rx_bytes add, three not-taken tests and
    one compare (drained vs ask).
  - C7 (60.31): no second listener; Config and Worker grow by one field each.
  - C6 (60.32 "Default changes"): no thread, no socket, no setsockopt.
  - PROXY (60.34): no pending map entry, no header read; `Worker::pending` stays empty and unallocated.
  - C4 step 2 (60.35): no side vector, no outbox; the hooks are behind one empty-vector test.
- Visible without a new flag (not behaviour):
  - `--help`: 14 new flags (upgrade notes).
  - Metrics line (`--metrics-interval`): 14 new keys (next section).
  - Error texts: two argument errors no longer echo the argument (C6: a non-UTF-8 argument, and an unknown argument
    that is not flag-shaped). Several flag errors were reworded (70.28): `--download-rate` / `--upload-rate-per-stream`
    and `--allow-ports` / `--block-ports` no longer contain `=` or `|`; the C10b texts say "at least", not `>=`; the
    C10b burst and `--proxy-protocol` errors now show the whole value on the command line (a `--config` line hides
    it, as for every flag). A script that matches error text must be checked; exit codes are unchanged.

## Upgrade notes (from base-5)
- **No flag was removed or renamed.** `--help` of fw-b5 (a5db9b7b) vs fw-b6rc1 (681fdd8e): 48 -> 62 flags, 0 gone,
  14 new: `--log-level`, `--log-conns`, `--log-streams`, `--metrics-listen`, `--download-rate`,
  `--upload-rate-per-stream`, `--upload-rate`, `--upload-rate-per-ip`, `--listen-unix`, `--unix-mode`, `--upstream`,
  `--upstream-trust-dns`, `--proxy-protocol`, `--proxy-protocol-from`. Each is also a `--config` key. A base-5 start
  command runs unchanged.
- Metrics line: 14 keys after `ip_keys_max` (above).
- `--log-level warn` or `error` also silences the info lines that base-5 always printed (listening, capabilities, hints,
  memory / tcp level lines below level 2, signal and drain lines, metrics lines). `--log-conns` and `--log-streams` are
  info: with `warn` / `error` they are off altogether.
- **`--log-streams` logs target hostnames** (and the client IP) for every stream and refused CONNECT: a privacy
  decision for the operator (40.01 "Logging"). Expect one line per stream; size the log sink for the stream rate.
  `--log-conns` logs client IPs, never hostnames.
- `--metrics-listen` has no auth and no TLS. Keep it on loopback (a bare PORT) or a private address; every
  non-loopback address prints a warning. A port in use, or the Wisp port, exits 2 at startup.
- `--download-rate` turns splice off for the whole process and caps the client lowat where one applies (60.30
  decision 4): more CPU per downloaded byte. It cannot pace unix-socket clients (startup warning with `--listen-unix`).
- `--upload-rate-per-ip` behind a reverse proxy needs `--trusted-proxy` (or `--listen-unix`, or PROXY protocol), else
  all clients share the proxy's key (40.01 "Upload caps").
- **Unix socket (`--listen-unix PATH`)**: who may connect = who may write the socket file. Mode 660 by default
  (`--unix-mode`, octal digits only); finalwisp has no group flag, so give the directory the proxy's group (systemd:
  `RuntimeDirectory=finalwisp`, `RuntimeDirectoryMode=2750`, `Group=www-data`). Its clients' X-Forwarded-For (or
  `--real-ip-header`) is believed like a trusted proxy's: only a proxy that sets the header may reach the socket.
  `PATH.lock` is held for the life of the process (a second instance on the path exits 1). Use a path no other program
  uses (40.01 "Reverse proxy").
- **`--upstream` is a secret flag** (C8): put the URL in a `--config` file with mode 0600; a group/world-readable
  config file that holds it, credentials on the command line (/proc/PID/cmdline) and credentials at all (clear text to
  the proxy) each print a warning. The URL is shown as `scheme://***@host:port`. With an upstream: UDP CONNECTs get 0x48,
  TCP Fast Open and the `--dns-own` early answers are off; `https://` proxies are refused at startup; `socks5h://`
  needs `--upstream-trust-dns` (the proxy resolves names; the address rules can then not be checked for names).
- **PROXY protocol** (`--proxy-protocol tcp|unix`): strict per listener: every connection on it must start with a
  v1 or v2 header, so turning it on cuts off clients that connect directly. `tcp` requires `--proxy-protocol-from
  CIDRS` (the balancers' addresses; others are reset at accept, metric `pp_refused`); a list with 0.0.0.0/0 or ::/0
  warns. `unix` requires `--listen-unix`. The header must arrive within 4-6 s (once up to ~8 s after an idle gap;
  `pp_timeout`).
- Error texts changed for several flags (above).

## What is new since base-5 (tag base-5, server code 5037a3b, md5 a5db9b7b)
- **C4 step 1 logging** (60.24; 40.01 "Logging"): `--log-level error|warn|info|debug` (default info);
  `--log-conns`: one logfmt `ev=conn_close` line per connection (ts, worker, cid, client IP and proxy, TLS, protocol,
  auth, duration, streams, refused CONNECTs, wire bytes rx/tx from TCP_INFO, close reason); `ev=conn_open` at debug;
  accept-time refusals as `ev=conn_refused` (20 per second per worker, then a suppressed count). One writer thread, a
  256 KiB outbox per worker; a slow stderr drops lines (metric `log_dropped`), never the server.
- **C4 step 2 stream log + C4 UDP counters** (60.35; 40.01 "Logging"): `--log-streams` (independent of
  `--log-conns`): one `ev=stream_close` line per stream (TCP, UDP, wsproxy `sid=0`) with host and port as sent, the
  connected address `dst`, up/down bytes (TCP_INFO for TCP; datagram and byte counts for UDP: `dgrams_up` /
  `dgrams_down`), the Wisp CLOSE reason, `why` and `rule` (the policy, limit or pressure rule that ended it); one
  `ev=stream_refused` per CONNECT refused before a target (20 per second per worker, `ev=stream_refused_suppressed`).
  With `--upstream`, `upstream=1`, and `dst` is the proxy. Log values escape every non-UTF-8 byte.
- **C5 Prometheus endpoint** (60.29; 40.01 "Metrics"): `--metrics-listen [ADDR:]PORT` serves `GET /metrics` (text
  format 0.0.4) from its own thread: the metrics line's values, counters `finalwisp_<name>_total`, base units,
  `finalwisp_close_total{reason}`, build_info; one scrape at a time, 2 s per connection. c5-fix: the time counters are
  read as one coherent set and never go back. **rx_bytes** (60.25, always on): client bytes read.
- **C10a bandwidth caps by kernel pacing** (60.30; 40.01 "Bandwidth caps"): `--download-rate RATE` per client
  connection, `--upload-rate-per-stream RATE` per TCP target (SO_MAX_PACING_RATE; bytes/s with K/M/G binary,
  16K..4095M); set once, no per-byte code; a startup self-check; a refused upload cap closes the stream with 0x03
  (`pace_fail`).
- **C10b upload caps** (60.25 "As built"; 40.01 "Bandwidth caps"): `--upload-rate R[/B]` per client connection and
  `--upload-rate-per-ip R[/B]` per client address (bytes/s K/M/G; R 8K..1T, burst B >= 16K and >= R/10): the server
  stops reading the client while over its budget (metrics `upl_pauses`, `upl_ip_waits`). Per IP, a starved-first
  ticket queue bounds the wait (no starvation; shares are not equalized). Behind a trusted proxy the bytes read
  before the client IP is known are charged once to that IP. The lease top-up (merged with the C10b notes) keeps the
  read size of an uncapped-speed upload at the OFF size (4.3 reads/MiB).
- **C7 unix socket listener** (60.31; 40.01 "Reverse proxy"): `--listen-unix PATH` adds a second listener (plain
  ws://; the TCP one stays), `--unix-mode OCTAL` (default 660). One shared socket, accepts handed to the least loaded
  worker; the unix peer is trusted for its client-IP header (sentinel `100::`; when the TCP peer address is read, i.e.
  with a C2/C3b flag or `--log-conns`, a TCP peer with exactly that address is reset, metric `refuse_sentinel`; without
  them no TCP client is trusted anyway); metric `accepted_unix`. Startup lock, leftover-socket replacement, unlink at shutdown.
- **C6 upstream proxy** (60.32; 40.01 "Upstream proxy"; wispurr parity, 60.18 #13 g / #17): `--upstream
  socks5://|socks5h://|http://[USER[:PASS]@]HOST[:PORT]` sends every TCP stream through one proxy; DNS and the destination
  policy stay local (`socks5h` + `--upstream-trust-dns`: names go to the proxy). Happy Eyeballs over the proxy's
  addresses, one deadline for the whole open, a retry on target refusals (up to 4 addresses), the proxy name refreshed
  every 30 s. Metrics `upstream_ok`, `upstream_fail` (+ refresh health for a proxy by name).
- **PROXY protocol v1/v2** (60.34; 40.01 "Reverse proxy"): `--proxy-protocol tcp|unix`, `--proxy-protocol-from
  CIDRS`: a header with a source address makes it the client (per-IP limits, logs; LOCAL / UNKNOWN keep the real peer),
  then the 60.22 trusted-proxy rules run on it.
  Strict parser (no TLV checks), header timeout 4-6 s, metrics `pp_ok`, `pp_local`, `pp_bad`, `pp_timeout`,
  `pp_refused`.
- **Fuzz campaign and redaction-mark test** (70.28): 4.36 G execs over 9 targets, 0 server bugs; 2 harness false
  positives led to reworded error texts; the regress corpora grew by 5218 files. The mark test
  (`cli::tests::error_texts_have_no_redaction_marks`) runs every flag with 48 plain values on the command line and as
  a `--config` key (plus argument shapes, cross-flag prerequisites and config-only marked values) and checks that no
  error text holds a redaction-marker character: the premise of the config-parse fuzz check that a `--config` value is
  never shown. It led to three error-text fixes, one of them a `--proxy-protocol` error that showed one entry of a
  value read from a `--config` line.
- Later, not base-6: an `https://` upstream proxy only if a site needs it (60.18 #17).

## Known limits
- **C4 logs** (60.24, 60.35): connections still open at a forced exit get no `conn_close` line. `rx` / `tx` are wire
  bytes (framing included); `tx` counts only acknowledged bytes. Lines over the 256 KiB outbox per worker are dropped
  (counted in `log_dropped`); `stream_close` lines are not rate-limited, refusal lines are (20 per second per worker).
  Stream lines are written at the end of the event-loop turn, not at the close instant (`dur_ms` uses the close time).
  A wsproxy stream has no Wisp CLOSE: its `reason` is always `none`. A refused host is cut to 255 bytes (`host_len=`).
  With `--dns-own`, a name whose early addresses are all refused and whose final answer is empty would log `dns_fail`,
  not `policy` (not reachable with today's resolver: the final answer repeats the early addresses; a debug_assert marks
  the contract; triage in the C4 step 2 work).
- **C5 endpoint** (60.29): no auth, no TLS; one scrape at a time (a stuck client delays the next by up to 2 s); no
  per-client labels; values per worker are not one global snapshot (the time counters are coherent).
- **C10a caps** (60.30): UDP upload not capped; no per-IP total (that is C10b); the first 10 TCP segments are not
  paced; the upload of a download-capped connection slows too; no effect on unix-socket clients (C7); the self-check
  proves inheritance, not that every route enforces the rate.
- **C10b caps** (60.25, 40.01 "Upload caps"): all streams of a limited connection wait together (head-of-line, as on
  a slow link), a credit-v2 pong too; per-IP shares are rough, not equal (the queue only prevents starvation; compat
  bound: the smaller share >= 15 %); an untracked key (full per-IP table, e.g. IPv6 /64 rotation) is fail open; burst
  B must be >= R/10 (100 ms resume tick); a connection may hold up to 512 KiB of its key's bucket while nobody waits.
- **C7 unix listener** (60.31): plain ws:// only; no dead-peer probe and no stall shed for unix clients (60.20 user
  answer f); no TCP_INFO byte counts in their log lines; `--download-rate` does not pace them; a socket another program
  bound but did not listen on yet counts as leftover and is replaced; an unparsable client-IP header from the unix peer
  charges one shared sentinel key.
- **C6 upstream proxy** (60.32): no `https://` proxy; UDP refused; credentials are clear text to the proxy; the proxy's
  own address is not checked by the address rules; with `socks5h` the address classes, own addresses, --allow-dest /
  --block-dest and --no-ipv6-targets cannot be applied to names; a proxy that sends no target-specific code gives 0x03
  for a refused target (ssh -D, tinyproxy, squid).
- **PROXY protocol** (60.34): strict per listener (no mixed direct and proxied clients); TLVs are skipped (no CRC32C
  check); header timeout 4-6 s (up to ~8 s after an idle gap); a header that completes at memory level 2-3 is still
  adopted (bounded by --max-conns and the timeout); a connection closed before any byte (a health check) gives no line.
- From base-5, unchanged: 60.23 Known limits.
